# گزارش فاز دوم — ارتقای عمیق منطق SYSTEM V1.0.0

## هدف
اتصال واقعی‌تر موتور چرخهٔ یادگیری به پنل مأموریت‌ها و هماهنگ‌سازی تصمیم‌های یادگیری با هدف فعال، نقطهٔ عطف، ارزیابی مهارت و پیوندهای موجود مأموریت؛ بدون تغییر قالب داده‌های ذخیره‌شده یا دادن پاداش از داخل موتور پیشنهاد.

## تغییرات اجراشده

### ۱. اتصال چرخهٔ یادگیری به اجرای برنامه
- در `js/app.js` رابط `SYSTEMLearningCycle` منتشر شد که هم ارزیابی چرخه و هم ساخت شواهد مرتبط با مأموریت تکمیل‌شده را فراهم می‌کند.
- `js/features/adaptive-learning-ui.js` اکنون در حضور هدف فعال از مسیر واحد `evaluateLearningCycle` استفاده می‌کند؛ مسیر پیشنهاددهی قدیمی فقط برای حالت بدون هدف سازگار باقی مانده است.
- خلاصهٔ هدف، فهرست نقاط عطف و توصیه‌های مأموریت از ارزیابی مشترک تغذیه می‌شوند. این موتور فقط می‌خواند و پیشنهاد می‌دهد.

### ۲. هماهنگی مهارت، هدف و شواهد
- `js/core/goal-progress.js` متد `toLegacyCurriculum` را برای تبدیل خواندنیِ قالب قدیمی هدف به تعریف قابل استفادهٔ موتور اضافه کرد.
- پیوند مهارت به هدف/نقطهٔ عطف فقط از پیوند صریح مأموریت گرفته می‌شود؛ شباهت نام، شاخه یا مقدار XP به تنهایی هیچ مهارتی را تأیید نمی‌کند.
- سابقهٔ ارزیابی و آمادگی مهارت همچنان از قرارداد موجود `SYSTEMSkillMastery` استفاده می‌کند. تکمیل مأموریت به معنی تسلط بر مهارت نیست.

### ۳. حفاظت از شواهد
- ساخت شواهد برای مأموریت ناقص، هدف اشتباه، نقطهٔ عطف ناشناخته، شناسهٔ تکراری یا زمان نامعتبر رد می‌شود.
- تأیید مهارت باید روش مجاز، زمان معتبر، شناسهٔ مهارت و امتیاز ۸۰ تا ۱۰۰ داشته باشد؛ امتیاز پایین نمی‌تواند به‌صورت اشتباه «تأیید» ثبت شود.
- چرخه و موتور پیشنهاد هیچ XP، سکه یا پاداشی اعطا نمی‌کنند. پرداخت پاداش همچنان در مسیرهای تراکنشی موجود باقی می‌ماند.

### ۴. بهترشدن انتخاب مأموریت بعدی
- شناسه‌های مأموریت تکمیل‌شده باید معتبر و یکتا باشند.
- ابتدا تنوع مهارت در توصیه‌ها حفظ می‌شود؛ اگر فقط یک مهارت گزینهٔ معتبر داشته باشد، موتور جایگاه‌های باقی‌مانده را با بهترین گزینه‌های جایگزین همان مهارت پر می‌کند، به‌جای بازگرداندن فهرست کوتاهِ غیرضروری.
- آزمون‌ها تکرار شناسه‌ها، پیوندها، عدم پرداخت پاداش، شواهد تأییدنشده و پرشدن جایگاه‌های توصیه را پوشش می‌دهند.

## اعتبارسنجی انجام‌شده
- `npm run build`: موفق؛ TypeScript کامپایل شد، CSS ساخته شد و Service Worker با ۱۴۸ منبع precache ساخته شد.
- `npm run test:ts`: موفق.
- `npm run test:static`: موفق، شامل آزمون جدید اتصال موتور چرخه به اجرای برنامه.
- `npm run architecture:check`: موفق.
- `npm run doctor`: موفق؛ با این هشدار که وابستگی Playwright در محیط نصب نشده است.
- `npm test`: موفق.
- `npm run prepare:android`: موفق؛ ۱۴۷ فایل و حدود ۶٫۱۶ مگابایت منبع وب در بستهٔ Android همگام شد.
- بررسی نحوی فایل‌های JavaScript تغییرکرده: موفق.

## محدودیت‌های صریح
- آزمون Playwright در مرورگر اجرا نشد، زیرا بستهٔ `@playwright/test` در محیط حاضر نصب نبود و نصب وابستگی‌ها در زمان مجاز به پایان نرسید.
- APK واقعی ساخته یا روی گوشی نصب نشده است؛ آزمون WebView، اعلان‌ها، حفظ داده بعد از بستن اپ و به‌روزرسانی درجا هنوز به آزمون دستگاه نیاز دارد.
- قالب قدیمی Goals همچنان هدف را بر اساس تعداد شواهدِ پیوندخورده مدل می‌کند. این فاز بدون مهاجرت یا تغییر مخرب داده‌های ذخیره‌شده، موتور تصمیم‌گیری را به همین مدل سازگار متصل می‌کند؛ ویرایشگر اختصاصی برای تعریف milestone و مهارت‌های اجباری هنوز اضافه نشده است.
