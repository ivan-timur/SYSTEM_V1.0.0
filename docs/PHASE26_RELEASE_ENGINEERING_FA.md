# فاز ۲۶ — دروازهٔ مهندسی انتشار

## هدف
پیش از ساخت APK، نسخهٔ مرجع برنامه و نسخهٔ بسته‌بندی‌شدهٔ وب را با یک بررسی خودکار کنترل کنیم تا خطاهای رایج انتشار زودتر آشکار شوند.

## مواردی که اکنون بررسی می‌شوند
- نسخهٔ `VERSION` با نسخهٔ `package.json` یکسان باشد.
- نسخهٔ Android `versionName` با نسخهٔ مرجع برابر باشد.
- نسخهٔ `manifest.webmanifest` با نسخهٔ مرجع برابر باشد.
- برای نسخهٔ فعلی، عنوانی در `CHANGELOG.md` وجود داشته باشد.
- فایل‌های کلیدی `index.html`، `sw.js`، `VERSION` و `manifest.webmanifest` در بستهٔ Android دقیقاً با نسخهٔ ریشه برابر باشند.
- چند مسیر رایج فایل امضا و `.env` به‌صورت ساده بررسی شوند تا اشتباهاً در پوشهٔ پروژه قرار نگرفته باشند.

## اجرا
پس از ساخت و همگام‌سازی منابع:

```bash
npm run prepare:android
npm run release:preflight
```

در GitHub Actions نیز این بررسی پیش از نصب ابزار Android و ساخت APK اجرا می‌شود.

## محدودیت‌ها
این دروازه جایگزین ساخت واقعی APK، امضای Release، آزمایش روی دستگاه، بررسی همهٔ فایل‌های محرمانه یا آزمون نصب/ارتقا نیست. بررسی نبود فایل‌های محرمانه فقط برای چند نام رایج است و اسکن کامل اسرار محسوب نمی‌شود.

## وضعیت وابستگی‌ها
در این بسته `package-lock.json` وجود ندارد. به همین دلیل، نصب وابستگی‌های npm هنوز کاملاً بازتولیدپذیر نیست و `npm ci` قابل استفاده نیست. ایجاد lockfile معتبر باید در محیطی با دسترسی سالم به npm registry انجام و سپس در مخزن ثبت شود.
