# فاز ۲۹ — ممیزی مرز هستهٔ پیشرفت

## هدف

این فاز، مرز میان رابط قدیمی، فرمان‌های TypeScript، جلوگیری از پاداش تکراری و ذخیره‌سازی موجود را با یک آزمون قراردادی صریح‌تر می‌کند. این فاز مهاجرت ذخیره‌سازی یا بازنویسی مسیر زنده را انجام نمی‌دهد؛ هدف جلوگیری از تغییر ناخواستهٔ رفتار موجود است.

## موارد کنترل‌شده

- مسیر زندهٔ پاداش باید ورودی را از قرارداد `prepareRewardCommand` عبور دهد.
- برای انواع پاداش اجباری، بررسی شناسهٔ تکراری باید قبل از نخستین تغییر Player انجام شود.
- تغییرات قدیمی رابط همچنان زیر پوشش `runSystemTransaction` باقی بمانند.
- `completeQuest` و اعتبارسنجی هویت رویداد XP در TypeScript باقی بمانند.
- نوشتن شناسهٔ جلوگیری از تکرار باید بررسی مجدد پس از ذخیره داشته باشد.
- `localStorage` تا زمان تصویب و آزمون مهاجرت همچنان منبع فعال رابط باقی می‌ماند.
- مهاجرت خودکار و نوشتن هم‌زمان کنترل‌نشده غیرفعال می‌مانند.

## آزمون

آزمون قراردادی: `tests/phase29-progression-boundary-audit-test.js`

دستور اجرای آزمون مستقل:

```sh
node tests/phase29-progression-boundary-audit-test.js
```

این آزمون ایستا است؛ وجود یا موفقیت آن جایگزین آزمون مرورگر، آزمون یکپارچه، ساخت APK یا آزمایش دستگاه واقعی نیست.

## محدودیت‌های باقی‌مانده

1. مسیرهای قدیمی هنوز برخی آثار جانبی را جداگانه در `localStorage` ثبت می‌کنند.
2. هستهٔ TypeScript هنوز به‌تنهایی تضمین‌کنندهٔ اتمی‌بودن همهٔ تغییرات UI نیست؛ این تضمین به لایهٔ تراکنش قدیمی نیز وابسته است.
3. مهاجرت کامل به IndexedDB انجام نشده است.
4. آزمون مرورگر و ساخت/نصب APK باید در محیط دارای وابستگی‌ها و Android SDK اجرا شود.

## معیار خروج

فاز بعدی نباید مهاجرت کامل را آغاز کند تا زمانی که مسیرهای فعال پاداش، rollback، حفظ داده، اجرای واقعی مرورگر و سازگاری منابع Android به‌طور مستقل تأیید شوند.
