# فاز ۲۵ — چک‌لیست آمادگی انتشار اندروید

این فاز بررسی‌های قابل‌تکرار انتشار را به پروژه اضافه می‌کند؛ این بررسی‌ها جای آزمون روی گوشی واقعی را نمی‌گیرند.

## بازسازی منابع و نسخه‌ها

از پوشهٔ اصلی پروژه اجرا کنید:

```bash
npm run prepare:android
npm run test:static
npm run doctor
```

`prepare:android` نسخهٔ canonical داخل `VERSION` را به متادیتای وب و Android همگام می‌کند، CSS و Service Worker را می‌سازد، TypeScript را کامپایل می‌کند و منابع وب را داخل `android/app/src/main/assets/www/` کپی می‌کند. آزمون Phase 25 بررسی می‌کند که فایل‌های کلیدی باندل Android دقیقاً با منابع انتشار یکسان باشند.

## آفلاین و WebView

- در نسخهٔ وب، Service Worker پوستهٔ برنامه و ماژول‌های کامپایل‌شده را پیش‌ذخیره می‌کند، کش‌های نسخهٔ قدیمی را پاک می‌کند و برای ناوبری آفلاین از `index.html` استفاده می‌کند.
- در اپ بومی Android، رابط از طریق `WebViewAssetLoader` با مبدأ HTTPS محلی و فایل‌های بسته‌بندی‌شده بار می‌شود؛ ثبت Service Worker وب در محیط بومی عمداً رد می‌شود. این باعث می‌شود فایل‌های محلی بدون اینترنت در دسترس باشند. قابلیت‌های AI که به سرویس آنلاین وابسته‌اند همچنان اینترنت می‌خواهند.
- تنظیمات بررسی‌شده شامل فعال بودن DOM Storage، غیرفعال بودن دسترسی `file://`، ممنوعیت محتوای ترکیبی ناامن و غیرفعال بودن ترافیک cleartext در Manifest است.

## آزمون دستی اجباری پیش از انتشار

روی دستگاه/شبیه‌ساز Android با همان نسخهٔ WebView مورد پشتیبانی، این فهرست را اجرا و نتیجه را ثبت کنید:

1. نصب تمیز APK آزمایشی؛ اجرای اولیه و باز کردن صفحات Status، Quest، Rewards، Settings و Skill Tree.
2. ساخت یک هدف و مأموریت آزمایشی، بستن کامل برنامه، اجرای مجدد و تأیید حفظ اطلاعات.
3. فعال کردن حالت پرواز، بستن اجباری و اجرای مجدد؛ تأیید بارگذاری پوسته و دارایی‌های محلی. آنلاین نبودن AI را خطای آفلاین پوسته تلقی نکنید.
4. نصب نسخهٔ جدید با همان شناسه و کلید امضای نسخهٔ قبلی؛ تأیید که Android آن را به‌روزرسانی می‌کند، نه نصب جداگانه، و اطلاعات برنامه باقی می‌ماند.
5. آزمایش خروجی پشتیبان و بازیابی در یک نمونهٔ آزمایشی قبل از حذف/إعادة نصب. به علت `allowBackup=false` نباید فرض کرد که حذف برنامه یا نصب تمیز اطلاعات را حفظ می‌کند؛ خروجی پشتیبان را جداگانه نگه دارید.
6. بررسی درخواست مجوز اعلان‌ها در Android 13+، زمان‌بندی یادآوری و رفتار پس از راه‌اندازی مجدد دستگاه.
7. بررسی پیوندهای خارجی، انتخاب فایل، export، چرخش/بازگشت و ورودی صفحه‌کلید.
8. در نسخهٔ انتشار، اطمینان از غیرفعال بودن WebView debugging و استفاده از همان کلید امضای پایدار برای تمام به‌روزرسانی‌ها.

## وضعیت این بسته

آزمون‌های قراردادی و ساخت منابع در خط لولهٔ پروژه قابل اجرا هستند. تا زمانی که APK با Android SDK ساخته و روی دستگاه/شبیه‌ساز اجرا نشده باشد، این بسته را «تأییدشده روی دستگاه» یا APK نهایی امضاشده تلقی نکنید. برای ساخت APK باید Android SDK Platform 36، Build Tools 36.0.0، JDK 17 و Gradle 8.13 در محیط Android آماده باشند.
