# گزارش ارتقای SYSTEM v2.1.0 — تشخیص مطمئن آزمون مرورگر و محافظت از Cutover

## خلاصه

این نسخه مشکل اجراکنندهٔ آزمون IndexedDB را اصلاح می‌کند تا دیگر به اتمام فرایند Chromium در حالت `--dump-dom` وابسته نباشد. آزمون از Chrome DevTools Protocol (CDP) و WebSocket داخلی Node.js استفاده می‌کند، وضعیت واقعی صفحه را بررسی می‌کند و میان «آزمون شکست‌خورده»، «صفحهٔ مسدودشده توسط سیاست مرورگر» و «آزمون موفق» تفاوت می‌گذارد.

**تغییر مسیر تولیدی مأموریت‌ها به IndexedDB عمداً انجام نشد.** علت این است که آزمون واقعی تراکنش باید پیش از Cutover موفق شود، اما سیاست مدیریتی Chromium در این محیط تمام URLها را مسدود می‌کند و صفحهٔ localhost قبل از اجرای جاوااسکریپت آزمون رد می‌شود. تغییر منبع ذخیره‌سازی بدون این تأیید، ریسک دوگانگی یا از دست‌رفتن پیشرفت را بالا می‌برد.

## تغییرات

- بازنویسی `tests/run-indexeddb-browser-test.js` با CDP، بدون وابستگی npm اضافی.
- محدودکردن سرور HTTP و رابط دیباگ Chromium به loopback (`127.0.0.1`).
- استفاده از پروفایل موقت مستقل برای اجرای آزمایش، زمان‌بندی محدود برای انتظار آغاز مرورگر/پاسخ فرمان‌ها، و پاک‌سازی منابع پس از اجرا.
- بررسی صفحهٔ واقعی با `Runtime.evaluate` به‌جای استنتاج نتیجه از خروج یا عدم خروج فرایند Chromium.
- تشخیص مستقیم `chrome-error://chromewebdata/` و متن مسدودسازی سازمانی، همراه با خطای صریح و سریع؛ چنین وضعیتی هیچ‌گاه «موفقیت» گزارش نمی‌شود.
- افزودن آزمون قرارداد برای loopback-only CDP، timeout محدود، وضعیت واقعی صفحه، تشخیص سیاست مدیریتی و حذف وابستگی به `--dump-dom`.
- به‌روزرسانی راهنماهای README و ساختار برای دستور آزمون جدید.
- حفظ همهٔ ۱۱ تم، کلیدهای ذخیرهٔ قدیمی، مسیر پاداش زنده و مهاجرت صریح؛ هیچ مهاجرت خودکاری انجام نشده است.

## آزمون‌های انجام‌شده

- `npm test` — **موفق**: build نسخه و TypeScript، CSS و Service Worker، تمام آزمون‌های TypeScript، تمام آزمون‌های ایستا/رگرسیون و آزمون جدید قرارداد اجراکننده.
- آزمون‌های Progression Math — **۱٬۵۳۱ بررسی موفق**.
- آزمون‌های مهارت — **۱٬۳۳۵ بررسی موفق در ۵۸۳ گره**.
- اعتبارسنجی JSON و smoke tests — **۲۵۱ بررسی موفق**.
- امنیت/ساخت — **۶۱ بررسی موفق**.
- حفظ همهٔ **۱۱ تم** — موفق.
- آزمون‌های Daily Prize، Goal، Profile، UI Layout، Android updater و release pipeline — موفق.
- `npm run test:browser-idb` — **به نتیجهٔ تراکنش نرسید**. اجراکنندهٔ جدید اکنون علت را شفاف مشخص کرد: Chromium تحت سیاست مدیریتی این محیط، URL محلی `127.0.0.1` را پیش از اجرای صفحه مسدود می‌کند (`Your organization doesn’t allow you to view this site`). این محدودیت محیط است، نه نتیجهٔ موفق یا ناموفق خود منطق IndexedDB؛ بنابراین تست واقعی ذخیره‌سازی را موفق اعلام نمی‌کنیم.

## آنچه انجام نشده است

- مسیرهای Daily Quest، AI Daily Quest، Custom Quest، Boss Quest و Goal به منبع IndexedDB تغییر ندادند.
- آزمون End-to-End تعاملی UI با Playwright اجرا نشد.
- APK واقعی ساخته یا روی دستگاه Android اجرا نشد؛ آماده‌سازی دارایی‌ها به‌تنهایی آزمون APK نیست.

## چرا این محدودیت حفظ شد؟

ذخیره‌سازی فعلی رابط هنوز از `localStorage` استفاده می‌کند؛ IndexedDB و مهاجرت در این نسخه جدا و opt-in باقی می‌مانند. نوشتن هم‌زمان پاداش در دو مخزن، بدون آزمون واقعی و بدون انتقال خواندن/نوشتن کل Player، Stat، Skill، history، counters و Quest، می‌تواند باعث ناهماهنگی یا دوباره‌پرداخت شود. بنابراین در این نسخه «پیشرفت معماری با دروازهٔ ایمنی» انجام شده، نه Cutover ناقص.

## اجرای آزمون در محیط توسعهٔ مجاز

```bash
npm run build
npm test
npm run test:browser-idb
```

محیط اجرا باید Chromium را نصب داشته باشد و سیاست سازمانی آن اجازهٔ بازکردن صفحهٔ HTTP محلی روی `127.0.0.1` را بدهد. پس از اجرای موفق آزمون واقعی IndexedDB، انتقال مرحله‌ای نخستین Quest باید با Backup، مهاجرت قابل‌برگشت و آزمون دوباره‌پرداخت آغاز شود.
