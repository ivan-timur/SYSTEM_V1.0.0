# راهنمای به‌روزرسانی وب SYSTEM بدون ساخت APK

## هدف

کانال `SYSTEM Web OTA` فایل‌های سازگار رابط کاربری و منطق JavaScript را از شاخهٔ خصوصی `system-ota` دریافت می‌کند. این کانال جدا از GitHub Releases است؛ انتشار بستهٔ وب APK تولید یا نصب نمی‌کند.

## نسخه‌ها

- `VERSION`: نسخهٔ برنامهٔ اندروید و نسخه‌ای که برای انتشار APK استفاده می‌شود.
- `WEB_VERSION`: نسخهٔ مستقل رابط کاربری و منطق وب. با هر انتشار تغییرات وب باید این شماره افزایش یابد؛ برای نمونه `1.0.0` به `1.0.1`.
- `WEB_MIN_NATIVE_VERSION`: کم‌ترین نسخهٔ Android Native که بستهٔ وب با آن سازگار است. آن را فقط وقتی تغییر بده که به قابلیت Native جدیدی نیاز باشد.

اگر فایل‌های وب را تغییر دادی ولی `WEB_VERSION` را افزایش ندادی، مرحلهٔ انتشار از انتشار محتوای متفاوت با همان شماره جلوگیری می‌کند.

## روند معمول برای تغییرات وب

۱. کدهای لازم را در `index.html`، پوشه‌های `css/`، `js/`، `data/` یا `src/` ویرایش کن.

۲. مقدار `WEB_VERSION` را افزایش بده. برای مثال، `1.0.0` را به `1.0.1` تغییر بده.

۳. تغییرات را به شاخهٔ `main` در GitHub بفرست.

۴. گردش‌کار `Publish SYSTEM web-only OTA bundle` آزمایش‌های پروژه را اجرا می‌کند، بستهٔ وب را می‌سازد و فقط فایل‌های لازم را در شاخهٔ `system-ota` منتشر می‌کند. این گردش‌کار مرحلهٔ `assembleRelease` یا `assembleDebug` ندارد و APK تولید نمی‌کند.

۵. در گوشی، بخش **Settings → App updates → Interface and feature updates** را باز کن و **Check web updates** را بزن. در صورت نمایش نسخهٔ تازه، **Apply web update** را انتخاب کن. SYSTEM بسته را دریافت می‌کند، چکیدهٔ SHA-256 و ساختار ZIP را بررسی می‌کند، سپس رابط را دوباره بارگذاری می‌کند.

برنامه به‌صورت خودکار نیز هر ۲۴ ساعت بررسی را آغاز می‌کند، به شرط آن‌که توکن GitHub قبلاً ذخیره شده باشد. اعمال نسخهٔ جدید به تأیید کاربر نیاز دارد.

## دسترسی GitHub

همان توکن محدود فعلی را استفاده کن: فقط مخزن `ivan-timur/SYSTEM_V1.0.0` و مجوز `Contents: Read-only`. توکن در Android Keystore رمزنگاری می‌شود. هرگز آن را در کد، فایل‌های پروژه یا گردش‌کار commit نکن.

شاخهٔ `system-ota` توسط GitHub Actions بازنویسی می‌شود؛ روی این شاخه قانون محافظتی‌ای تنظیم نکن که force-push گردش‌کار را مسدود کند. شاخهٔ اصلی `main` جدا باقی می‌ماند.

## چه وقت APK تازه لازم است؟

تغییرات HTML، CSS، JavaScript، داده‌ها و منطق وب معمولاً می‌توانند از کانال OTA بیایند. تغییرات Java/Kotlin، پل `SYSTEMAndroid`، مجوزهای اندروید، وابستگی‌های Native، شناسهٔ بسته یا تنظیمات ساخت همچنان به انتشار و نصب APK تازه نیاز دارند. برای قابلیت‌هایی که به Native جدید وابسته‌اند، ابتدا APK سازگار را منتشر کن و سپس `WEB_MIN_NATIVE_VERSION` را برای بستهٔ وب مناسب تنظیم کن.

## امنیت و بازیابی

بسته فقط پس از بررسی اندازه، SHA-256، مسیرهای ZIP، حجم استخراج‌شده و نسخهٔ داخل بسته فعال می‌شود. فایل‌ها در فضای خصوصی برنامه ذخیره می‌شوند؛ کد اجرایی از URL دوردست مستقیماً در WebView اجرا نمی‌شود. نسخهٔ قبلی حفظ می‌شود و اگر برنامه پیش از تکمیل نخستین بارگذاری پس از ارتقا بسته شود، اجرای بعدی به نسخهٔ قبلی برمی‌گردد.

SHA-256 خرابی یا تفاوت فایل را تشخیص می‌دهد، اما جای حفاظت از حساب GitHub و توکن را نمی‌گیرد. برای توزیع از فروشگاه‌ها، قواعد همان فروشگاه دربارهٔ دریافت کد اجرایی از اینترنت را جداگانه بررسی کن.
