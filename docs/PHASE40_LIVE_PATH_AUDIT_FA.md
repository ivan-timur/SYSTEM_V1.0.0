# فاز ۴۰ — ممیزی مسیرهای اجرایی و مرز ذخیره‌سازی

## هدف

این فاز مرز ذخیره‌سازی فعال را مستند و با آزمون قراردادی محافظت می‌کند؛ بدون تغییر خودکار پایگاه داده، بدون حذف داده‌های قدیمی و بدون فعال‌کردن مهاجرت سراسری.

## یافته‌های تأییدشده از کد

- ورودی برنامه از `js/app.js` به‌عنوان ES module بارگذاری می‌شود.
- رابط قدیمی هنوز از `localStorage` استفاده می‌کند.
- ابزار مهاجرت به IndexedDB به‌صورت API صریح ارائه شده است: پیش‌نمایش، ساخت تأییدیه و اجرای مهاجرت از هم جدا هستند.
- API پایدار برای پیشرفت و برنامهٔ درسی به‌صورت opt-in در دسترس است؛ این موضوع به معنی اتصال تمام جریان‌های رابط به آن نیست.
- آزمون مرورگر IndexedDB و فرمان ساخت APK دیباگ در `package.json` تعریف شده‌اند؛ وجود فرمان‌ها به معنی اجرای موفق آن‌ها نیست.
- `package-lock.json` در بستهٔ Phase 39 وجود نداشت. تولید آفلاین آن در محیط ممیزی ناموفق شد، چون اطلاعات registry وابستگی‌ها در کش محلی نبود. فایل قفل ساختگی ایجاد نشد.

## تصمیم ایمنی

تا وقتی آزمون مرورگر واقعی، ساخت APK و آزمون نصب/بازیابی دستگاه انجام نشده، منبع اصلی ذخیره‌سازی به IndexedDB تغییر نمی‌کند. هیچ مهاجرت خودکار یا حذف نسخهٔ localStorage مجاز نیست.

## آزمون افزوده‌شده

`tests/phase40-live-path-audit-test.js` موارد زیر را کنترل می‌کند:

1. حفظ مرز صریح مهاجرت؛
2. جدابودن پیش‌نمایش، تأیید و اجرا؛
3. حفظ وضعیت فعلی رابط قدیمی؛
4. وجود مسیر IndexedDB و فرمان‌های اعتبارسنجی مرورگر/Android؛
5. گزارش وضعیت فایل قفل وابستگی‌ها و تعداد تقریبی ارجاع‌های localStorage در چند فایل کلیدی.

شمارش ارجاع‌های localStorage صرفاً شاخص ایستا است و جایگزین تحلیل کامل call graph یا آزمون زمان اجرا نیست.

## دروازه‌های انتشار باقی‌مانده

- تولید `package-lock.json` با دسترسی registry و نصب بازتولیدپذیر؛
- اجرای `npm test` في بيئة تحتوي على dependencies؛
- اجرای `npm run test:browser-idb` در مرورگر واقعی؛
- اجرای `npm run android:build:debug` با Android SDK/Gradle؛
- نصب APK و آزمون تکمیل مأموریت، راه‌اندازی مجدد، نگهداری داده و ارتقا؛
- بررسی بصری تمام صفحات روی دستگاه واقعی.
