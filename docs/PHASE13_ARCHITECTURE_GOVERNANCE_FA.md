# فاز ۱۳ — تثبیت نقشهٔ معماری و جلوگیری از انحراف

## هدف
نقشهٔ معماری نهایی را از یک سند توضیحی به یک قرارداد قابل‌آزمون تبدیل می‌کند؛ بدون فعال‌کردن فناوری‌های آینده صرفاً برای کامل‌کردن فهرست.

## تغییرات
- افزودن `tests/phase13-architecture-roadmap-contract-test.js`.
- اتصال آزمون قرارداد به `npm run test:static` و در نتیجه مسیر استاندارد `npm test`.
- بررسی وجود مسئولیت همهٔ فناوری‌های اعلام‌شده در نقشه.
- بررسی مالکیت منطق پیشرفت در TypeScript، نقطهٔ ورود ES Module، و وجود آداپتور IndexedDB.
- محافظت قراردادی از مهاجرت ذخیره‌سازی: جریان بازبینی/تأیید حفظ شود و پل فاز ۱۲ همچنان از نوشتن دوگانه جلوگیری کند.
- ثبت این اصل که SQLite، Kotlin، سرور AI، Rust/WASM و ICU فقط پس از اثبات نیاز و داشتن آزمون مناسب وارد runtime می‌شوند.

## اصولی که تغییر نمی‌کنند
1. `localStorage` تا زمان عبور از دروازهٔ مهاجرت همچنان منبع زندهٔ رابط است.
2. راه‌اندازی برنامه به‌تنهایی نباید مهاجرت ذخیره‌سازی را اجرا کند.
3. قوانین XP، Level، Rank و Quest در لایهٔ TypeScript باقی می‌مانند؛ UI فقط فرمان/نمایش را مدیریت می‌کند.
4. فایل‌های تولیدشده به‌صورت دستی منبع حقیقت نیستند و باید از سورس ساخته شوند.
5. قبولی آزمون ایستا به معنی تأیید اجرای واقعی Android WebView یا آزمون مرورگر IndexedDB نیست.

## اعتبارسنجی
آزمون جدید با فرمان زیر اجرا می‌شود:

```sh
node tests/phase13-architecture-roadmap-contract-test.js
```

یا همراه آزمون‌های ایستا:

```sh
npm run test:static
```

در محیطی که وابستگی‌های پروژه نصب نشده‌اند، اجرای کامل `npm test` هنوز به نصب وابستگی‌های قفل‌شده و اجرای build نیاز دارد. هیچ ادعایی دربارهٔ موفقیت آزمون کامل یا ساخت APK بدون اجرای واقعی آن مطرح نمی‌شود.

## دروازهٔ فاز بعدی
پیش از تغییر منبع ذخیرهٔ اصلی، باید آزمون IndexedDB در مرورگر واقعی، مهاجرت با پیش‌نمایش و تأیید، نسخهٔ پشتیبان قابل‌بازیابی، و مسیر rollback در دستگاه Android بررسی شوند.
