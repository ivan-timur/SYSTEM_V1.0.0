# گزارش فاز ۱۰ — یکپارچه‌سازی معماری SYSTEM

## هدف
ایجاد یک دروازهٔ کنترل معماری که پیش از انتشار، مسیرهای واردات محلی، فایل‌های ضروری، نسخهٔ واحد و مرزهای مهم ذخیره‌سازی و پیشرفت را بررسی کند؛ بدون بازنویسی پرخطر کنترلر قدیمی یا تغییر قالب ذخیره‌های کاربر.

## تغییرات
- اسکریپت `scripts/phase10-architecture-audit.js` افزوده شد.
- بررسی تطبیق `VERSION` با `package.json`، `manifest.webmanifest`، `sw.js` و `android/app/build.gradle` اضافه شد.
- واردات نسبی در پوشه‌های `src/` و `js/` و `scripts/` بررسی می‌شود؛ مشخص‌کننده‌های TypeScript با پسوند `.js` می‌توانند به فایل منبع `.ts` متناظر resolve شوند.
- وجود فایل‌های اصلی هستهٔ TypeScript، فرمان‌های Quest، اعتبارسنجی داده‌ها، IndexedDB، مهاجرت و آزمون‌های تراکنش بررسی می‌شود.
- ارجاع اسکریپت‌های npm به فایل‌های جاوااسکریپت محلی کنترل می‌شود.
- آزمون معماری فاز ۱۰ به مسیر `test:static` افزوده شد تا در `npm test` اجرا گردد.
- فناوری‌های SQLite و Rust/WebAssembly بدون نیاز اثبات‌شده وارد وابستگی‌های runtime نمی‌شوند.

## مرزهای ایمنی که حفظ شدند
- منطق XP/Level/Rank و تکمیل Quest در TypeScript باقی می‌ماند.
- localStorage همچنان منبع فعال UI قدیمی است؛ مهاجرت به IndexedDB خودکار نشده است.
- مهاجرت نیازمند preview، approval صریح، بررسی fingerprint و تأیید هشدارها باقی می‌ماند.
- آزمون‌های rollback باید هم دادهٔ ذخیره‌شده و هم شکل state در حافظه را پوشش دهند.
- خروجی‌های CSS، Service Worker و TypeScript با فرایند build تولید می‌شوند و نباید منبع اصلی ویرایش باشند.

## اجرا و اعتبارسنجی
```sh
npm run build
npm run architecture:phase10
npm test
npm run doctor
```

## محدودیت گزارش
آزمون‌های Node و قراردادهای ایستا، جای آزمون واقعی مرورگر برای رقابت/rollback در IndexedDB یا آزمون نصب و به‌روزرسانی روی دستگاه Android را نمی‌گیرند. این آزمون‌ها باید در محیطی که مرورگر و Android SDK در دسترس‌اند اجرا شوند. در نبود `package-lock.json`، نصب با `npm ci` نیز از این آرشیو قابل بازتولید نیست؛ این مورد به‌عنوان هشدار گزارش می‌شود و به‌دلیل محدودیت دسترسی نصب، lockfile حدسی تولید نشده است.
