# گزارش فاز ۶ — گردش‌کار مهاجرت و دروازهٔ تغییر منبع ذخیره‌سازی

**نسخه:** SYSTEM V1.0.0  
**تاریخ:** ۱۹ اکتبر ۲۰۲۶

## انجام‌شده

- پنل «IndexedDB migration» در مسیر Settings → Backup اضافه شد.
- کاربر ابتدا پیش‌نمایش ذخیرهٔ فعلی را می‌بیند: تعداد مأموریت‌ها، مأموریت‌های تکمیل‌شده، رویدادهای XP، مهارت‌ها، شاخه‌ها و فعالیت‌ها.
- واردکردن فقط پس از تأیید جداگانه انجام می‌شود؛ هشدارها نیازمند تأیید هستند.
- وضعیت رسید مهاجرت از IndexedDB به‌شکل فقط‌خواندنی خوانده می‌شود.
- fingerprint ذخیرهٔ فعلی با fingerprint واردشده مقایسه می‌شود تا تغییرات پس از مهاجرت پنهان نماند.
- واردکردن خودکار نیست، داده‌های `localStorage` حذف نمی‌شوند و پایگاه مقصد غیرخالی با داده‌های موجود بازنویسی نمی‌شود.
- آزمون قراردادی جدید به `npm test` اضافه شد.

## اعتبارسنجی انجام‌شده

- `npm test` — موفق؛ آزمون‌های TypeScript، آزمون‌های ایستا، بررسی‌های رگرسیون و نگهبان معماری.
- `node --check js/app.js` — موفق.
- `node --check js/legacy/app-controller.js` — موفق.
- `node tests/phase25-android-release-readiness-test.js` — موفق؛ ۴۲ بررسی.
- `node scripts/architecture-guard.js` — موفق.
- همگام‌سازی منابع اندروید — موفق؛ ۱۴۸ فایل.

## محدودیت‌های روشن

- اجرای `npm run test:browser-idb` تلاش شد اما سیاست مدیریتی Chromium دسترسی صفحهٔ آزمون به localhost را مسدود کرد (`ERR_BLOCKED_BY_ADMINISTRATOR` و `URLBlocklist: ["*"]`). هیچ نتیجهٔ واقعی IndexedDB از این اجرا به‌دست نیامد و آن را قبولی آزمون حساب نکردیم.
- آزمون Playwright سرتاسری و نصب واقعی روی دستگاه اندروید انجام نشده است؛ APK ساخته نشده است.
- **منبع اصلی رابط زنده هنوز `localStorage` است.** این فاز گردش‌کار مهاجرت و تشخیص واگرایی را به رابط اضافه می‌کند، اما هنوز همهٔ مسیرهای پاداش و پیشرفت را به تراکنش واحد IndexedDB انتقال نمی‌دهد. به‌همین دلیل، فعال‌سازی سراسری IndexedDB عمداً انجام نشده است.

## گام بعدی

انتقال هر دستهٔ مأموریت و پاداش به فرمان‌های اتمی، سپس همگام‌سازی قابل‌بازیابی رابط از منبع منتخب و اجرای آزمون واقعی مرورگر در CI مجاز، پیش از هرگونه تغییر سراسری منبع داده.
