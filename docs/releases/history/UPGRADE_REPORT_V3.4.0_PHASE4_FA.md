# گزارش ارتقای SYSTEM v3.4.0 — فاز چهارم

## هدف
اتصال قرارداد تایپ‌شدهٔ Goal Curriculum به Goalهای موجود، بدون شکستن داده‌های قبلی و بدون جابه‌جایی اختیار پرداخت XP و Coin.

## تغییرات
- یک پل سازگاری فقط‌خواندنی به `SYSTEMGoalProgress.evaluateLegacyCurriculum` افزوده شد.
- هر هدف قدیمی بر اساس `targetCount` به مسیر ترتیبی Milestone تبدیل می‌شود؛ شواهد یکتای موجود به نقاط عطف متناظر نگاشت می‌شوند.
- شواهد قدیمی که Stat ندارند، در هدف شاخه‌دار با Stat خود هدف ارزیابی می‌شوند تا سابقهٔ معتبر قبلی ناپدید نشود.
- پنجرهٔ Goals اکنون تعداد Milestoneهای تکمیل‌شده و مسیر بازشدن/قفل‌بودن آن‌ها را نمایش می‌دهد.
- اگر ارزیاب تایپ‌شده در دسترس نباشد یا داده قابل ارزیابی نباشد، رابط به نمایش قدیمی برمی‌گردد.
- عملیات ارزیابی هیچ ذخیره‌سازی، حذف، مهاجرت خودکار یا پاداشی انجام نمی‌دهد؛ تکمیل دستی و پاداش‌ها همچنان از مسیر تراکنش قبلی عبور می‌کنند.

## آزمون‌ها
آزمون‌های قرارداد پل سازگاری و اتصال UI افزوده شدند. نتایج نهایی `npm test` و `npm run doctor` باید در محیط ساخت این نسخه بررسی شوند؛ APK و آزمون واقعی روی دستگاه در این مرحله ادعا نمی‌شوند.

## نتیجهٔ اجرای ساخت در این محیط
- `npm test`: موفق؛ شامل آزمون‌های TypeScript، آزمون‌های ایستا/رگرسیون و بررسی معماری.
- `npm run doctor`: موفق؛ متادیتای انتشار و فایل‌های اصلی هماهنگ‌اند.
- `npm run prepare:android`: موفق؛ ۱۴۰ فایل وب با حجم حدود ۶٫۰۷ MiB به دارایی‌های Android همگام شدند.
- Service Worker با ۱۴۱ منبع هم‌مبدأ ساخته شد؛ ۶۴ stylesheet منبع بررسی شد و صفر `!important` در CSS runtime گزارش شد.
- وابستگی Playwright در این محیط نصب نیست؛ بنابراین آزمون E2E واقعی مرورگر اجرا نشده است. APK نیز ساخته یا روی دستگاه آزمایش نشده است.
