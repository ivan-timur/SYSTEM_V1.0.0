# گزارش ارتقای SYSTEM v3.2.2 — فاز دوم: سلامت ذخیره‌سازی و تشخیص یکپارچگی

## هدف فاز
تقویت محافظت از داده‌ها بدون فعال‌کردن مهاجرت خودکار و بدون حذف یا بازنویسی اطلاعات قدیمی. این فاز ابزار تشخیصی فقط‌خواندنی برای IndexedDB اضافه می‌کند تا پیش از مهاجرت گسترده‌تر، وضعیت ساختاری پایگاه داده قابل بررسی باشد.

## تغییرات انجام‌شده
- افزودن `src/storage/database-health.ts` با تابع `inspectSystemDatabase()`.
- خواندن فروشگاه‌های IndexedDB در یک تراکنش `readonly`.
- گزارش نسخهٔ مورد انتظار و نسخهٔ واقعی پایگاه داده، زمان بررسی و شمار رکوردهای هر فروشگاه.
- تشخیص نبودن بازیکن اصلی در پایگاه داده‌ای که دادهٔ پیشرفت دارد.
- تشخیص چند رکورد بازیکن، هویت‌های نامعتبر مأموریت‌ها، رویدادهای XP ناقص/نامعتبر و ارجاع رویداد XP به مأموریت ناموجود.
- بررسی شناسه و timestamp رکوردهای تاریخچهٔ فعالیت.
- دسته‌بندی نتیجه به `empty`، `healthy`، `warning` یا `error`.
- نمایش API تشخیصی به‌صورت `window.SYSTEMStorageDiagnostics.inspectIndexedDB()`.
- افزودن آزمون قراردادی که تضمین می‌کند لایهٔ تشخیص از مسیرهای نوشتن IndexedDB استفاده نمی‌کند.
- ارتقای نسخه به 3.2.2 و بازسازی فایل‌های خروجی TypeScript، CSS و Service Worker.

## ایمنی داده‌ها
- مهاجرت `localStorage` به IndexedDB همچنان فقط با پیش‌نمایش، تأیید صریح و تأیید هشدارها قابل اجرا است.
- این فاز هیچ داده‌ای را پاک، تعمیر، جابه‌جا یا بازنویسی نمی‌کند.
- گزارش سلامت یک ابزار تشخیصی است؛ اگر هشدار یا خطا پیدا شود، اصلاح خودکار انجام نمی‌دهد.
- اثرانگشت مهاجرت موجود، هشدارهای مهاجرت و مرز عدم حذف کلیدهای قدیمی دست‌نخورده باقی مانده‌اند.

## آزمون‌ها
- `npm test` — موفق.
- ساخت TypeScript و runtime — موفق.
- ساخت CSS — موفق؛ 64 فایل منبع، صفر اعلان `!important` در خروجی runtime.
- ساخت Service Worker — موفق؛ 140 منبع same-origin در فهرست precache.
- آزمون‌های TypeScript — موفق، از جمله آزمون قرارداد جدید برای تشخیص پایگاه داده.
- آزمون‌های static/regression — موفق.
- Architecture Guard — موفق.

## محدودیت‌هایی که هنوز باید روشن بمانند
- آزمون مرورگر واقعی برای IndexedDB در این اجرای فاز اجرا نشده است؛ وجود آزمون browser test در پروژه، نتیجهٔ اجرای آن نیست.
- APK در این فاز ساخته یا روی Android آزمایش نشده است.
- این فاز هنوز مرجع عمومی ذخیره‌سازی runtime را از `localStorage` به IndexedDB منتقل نمی‌کند.
- گزارش تشخیصی فقط مشکلات قابل‌شناسایی در قواعد پیاده‌سازی‌شده را می‌بیند و جایگزین پشتیبان‌گیری یا آزمون بازیابی نیست.

## نتیجه
فاز دوم یک لایهٔ تشخیص فقط‌خواندنی به ذخیره‌سازی اضافه کرد و ابزار بررسی ساختاری را از رابط کاربری جدا نگه داشت. گام بعدی باید افزودن/تکمیل آزمون مرورگر واقعی و سپس طراحی بستهٔ پشتیبان‌گیری/بازیابی IndexedDB با اعتبارسنجی، تأیید صریح و سیاست بازگشت امن باشد؛ نه فعال‌کردن مهاجرت خودکار.
