# گزارش ارتقای SYSTEM v2.3.0 — موتور اتمیک Daily Quest Streak

## خلاصهٔ اجرایی

در v2.3.0 گام دامنه‌ای بعد از جداسازی سرویس Daily Quest انجام شد: محاسبهٔ زنجیرهٔ روزهای پیوسته (Streak) به TypeScript انتقال یافته و مسیر تراکنش IndexedDB برای ثبت زنجیره و پاداش‌های وابسته آماده شده است. قاعدهٔ پایهٔ محصول حفظ می‌شود: **هر روز پیوسته +۵٪ XP، با سقف +۵۰٪؛ مأموریت‌های اضافی در همان روز زنجیره را جلو نمی‌برند.**

این نسخه همچنان یک مرز ایمنی مهم را رعایت می‌کند: اتصال دکمه‌های زندهٔ Daily Quest به IndexedDB فعال نشده است؛ چون سیاست Chromium مدیریت‌شده، صفحهٔ محلی آزمون را پیش از اجرای آزمون مسدود می‌کند. این نسخه زیرساخت و آزمون‌های آن را آماده‌تر کرده، اما نتیجهٔ واقعی اجرای تراکنش در مرورگر هنوز تأیید نشده است.

## تغییرهای فنی

### ۱. موتور مستقل Streak در TypeScript

فایل `src/core/daily-quest-streak.ts` اضافه شد. این ماژول خالص و مستقل از DOM و ذخیره‌سازی است و:

- روز تقویمی واقعی را اعتبارسنجی می‌کند؛ تاریخ‌هایی مانند ۳۰ فوریه پذیرفته نمی‌شوند.
- روز اول را با ضریب 1.00 آغاز می‌کند؛ برای روزهای پیوسته، هر روز 0.05 به ضریب می‌افزاید تا سقف 1.50.
- تکمیل چند Daily Quest در یک روز را فقط یک روز فعالیت حساب می‌کند و ضریب همان روز را حفظ می‌کند.
- با جاافتادن یک یا چند روز، زنجیرهٔ جاری را به روز اول بازمی‌گرداند، ولی رکورد بهترین زنجیره را نگه می‌دارد.
- بازگشت تاریخ به گذشته، تاریخ نامعتبر یا رکورد ذخیرهٔ خراب را رد می‌کند؛ در نتیجه تغییر ساعت به عقب نباید بی‌صدا زنجیرهٔ پیشرفت را دست‌کاری کند.
- هیچ تغییری را خودش ذخیره نمی‌کند؛ فراخواننده باید حالت برگشتی را در همان تراکنش پاداش بنویسد.

### ۲. افزودن Streak به تراکنش اتمیک IndexedDB

در `src/storage/indexeddb.ts`، مسیر `completeQuestInDatabase()` اکنون برای مأموریت‌های اصلی Daily Quest می‌تواند زنجیره را بخواند، مقدار بعدی را محاسبه کند و آن را با تمام اثرهای تکمیل Quest در یک تراکنش `readwrite` ذخیره کند. مسیر آماده‌شده شامل Player، Quest، دفتر XP، Skillها، Stat، Achievements، تاریخچهٔ فعالیت، شمارنده‌ها، Daily Prize و رکورد Streak است.

اگر اعتبارسنجی XP یا هر مرحلهٔ حیاتی دیگر شکست بخورد، تراکنش باید abort شود؛ بنابراین حالت Streak نباید جدا از پاداش ثبت گردد. این رفتار در آزمون واقعی مرورگر هدف‌گذاری شده، اما اجرای واقعی آن در محیط فعلی مسدود است و هنوز به‌عنوان تأییدشده گزارش نمی‌شود.

### ۳. نگه‌داشتن XP پایه و ثبت XP واقعی

- مقدار اصلی `quest.xpReward` به‌عنوان XP پایه حفظ می‌شود.
- XP تعدیل‌شده با Streak در فیلد جداگانهٔ `awardedXP` ذخیره می‌شود؛ برای مثال مأموریت 100 XP در روز دوم 105 XP می‌دهد، در حالی که XP پایه همچنان 100 باقی می‌ماند.
- دفتر XP و اعتبارسنجی تکرار از XP واقعی اعطاشده استفاده می‌کنند تا ذخیرهٔ دوباره یا بازپخش یک Quest با XP متفاوت پذیرفته نشود.
- تاریخچهٔ فعالیت مقدار XP پایه، پاداش اضافهٔ Streak، ضریب و تعداد روزهای زنجیره را ثبت می‌کند.
- XP بازیکن، Stat و Skill در اثر Streak هماهنگ مقیاس می‌شود؛ پاداش Daily Prize جدا از XP/Skill/Stat مأموریت باقی می‌ماند.

### ۴. مهاجرت امن Streak قدیمی

برنامه‌ریز مهاجرت `src/storage/legacy-migration.ts` کلید موجود `system_v2_quest_streak` را در پیش‌نمایش و مهاجرت اختیاری لحاظ می‌کند. تاریخ و مقدار Streak بررسی می‌شوند؛ رکورد ناسالم، بدون بازنشانی خاموش رد می‌شود.

ساختار قدیمی فقط `last` و `streak` را نگه می‌داشت و سابقهٔ مستقل برای بهترین زنجیره در دسترس نیست؛ به همین دلیل `bestStreak` هنگام ورود با مقدار Streak فعلی آغاز می‌شود. این محدودیت اطلاعاتی در گزارش ثبت شده است. مهاجرت هنوز اختیاری است و کلیدهای `localStorage` را پاک یا بازنویسی نمی‌کند.

### ۵. دامنهٔ اعمال

- Streak فقط به شش Daily Quest اصلی تعلق دارد.
- AI Daily، Custom Quest و Boss Quest به‌خودی‌خود زنجیرهٔ روزانه را افزایش نمی‌دهند.
- سرویس `src/features/daily-quest-command.ts` اثر Streak را فقط برای Quest اصلی ایجاد می‌کند.
- مسیر دکمه‌های قدیمی و منبع ذخیره‌سازی رابط زنده هنوز `localStorage` است؛ هنوز cutover انجام نشده است.
- هر ۱۱ تم موجود حفظ شده‌اند و Schema نسخهٔ ۴ به تغییر Object Store جدید نیاز نداشته است؛ رکورد Streak در Store موجود `app_state` قرار می‌گیرد.

## آزمون‌ها و راستی‌آزمایی

### موارد اجراشده و موفق

- `npm test` — **موفق**؛ ساخت TypeScript و runtime، تولید CSS و Service Worker، آزمون‌های TypeScript و تمام آزمون‌های static/regression تعریف‌شده اجرا شدند.
- آزمون‌های خالص Streak — **۲۴ بررسی موفق**؛ شامل توالی روزها، چند Quest در یک روز، بازنشانی، سقف ۵۰٪، روز کبیسه، تغییر سال و ورودی خراب.
- آزمون سرویس Daily Quest — **۲۵ بررسی موفق**؛ شامل شناسه‌های canonical و alias، منبع معتبر پاداش، جدایی AI Daily، metadata و دروازهٔ Daily Prize.
- آزمون‌های مهاجرت — موفق؛ شامل انتقال Streak قدیمی و رد دادهٔ ناسالم.
- آزمون‌های progression math — **۱۵۳۱ بررسی**.
- آزمون‌های Skill progression — **۱۳۳۵ بررسی در ۵۸۳ گرهٔ برنامهٔ درسی**.
- آزمون‌های smoke/unit — **۲۵۱ بررسی**؛ ۲۶ فایل JSON بررسی شدند.
- آزمون‌های project integrity — **۸۰ بررسی**؛ نسخهٔ انتشار 2.3.0.
- بررسی‌های تم — هر **۱۱ تم** حفظ شده‌اند.
- قرارداد مرورگر/IndexedDB — موفق؛ فایل آزمون مرورگر از نظر نحو JavaScript بررسی شد و پوشش سناریوهای award/replay/rollback و مهاجرت Streak بررسی ایستا شد.
- `npm run doctor` — موفق؛ فایل‌های runtime و metadata سازگار هستند. این محیط وابستگی Playwright را نصب‌شده تشخیص نداد، هرچند آزمون‌های static کامل اجرا شدند.
- `npm run prepare:android` — موفق؛ ساخت وب اجرا شد و **۱۳۱ فایل با حجم حدود 5.99 MiB** به دارایی‌های Android همگام شدند.
- `unzip -t` — سلامت بستهٔ نهایی بررسی شد.

### مواردی که تأیید نشدند

- `npm run test:browser-idb` — **نتیجهٔ مرورگر تولید نشد**؛ Chromium صفحهٔ محلی آزمون را با `net::ERR_BLOCKED_BY_ADMINISTRATOR` مسدود کرد. این مورد محدودیت سیاست محیط است، نه نتیجهٔ موفق آزمون تراکنش. از آن برای دورزدن سیاست مرورگر استفاده نشده است.
- APK واقعی ساخته، نصب یا روی دستگاه Android اجرا نشده است. `prepare:android` فقط اپ وب را build و assetهای آن را با پروژهٔ Android همگام می‌کند.
- اتصال مسیر زندهٔ Daily Quest به IndexedDB هنوز فعال نشده است.

## معیار گام بعدی

پیش از cutover باید `npm run test:browser-idb` در یک محیط Chromium مجاز اجرا شود و نتیجهٔ واقعی برای این سناریوها تأیید گردد: مهاجرت Streak، محاسبهٔ روز دوم، چند تکمیل در یک روز، عدم پرداخت دوباره، حفظ XP پایه، تطبیق Player/Stat/Skill، rollback تراکنش ناقص و شرط Daily Prize. پس از عبور از این دروازه، تنها Daily Quest باید به رابط زنده متصل و با ذخیره‌های واقعی قدیمی regression-test شود؛ سپس می‌توان به سراغ AI Daily، Custom و Boss رفت.

**نتیجه:** v2.3.0 موتور Streak و مسیر تراکنشی لازم را پیاده و آزمون‌های مستقل، ساخت و بسته‌بندی را با موفقیت گذرانده است. اما به‌صورت شفاف، آزمون واقعی مرورگر و انتقال زنده هنوز تأیید نشده‌اند؛ `localStorage` در رابط فعلی همچنان منبع معتبر باقی می‌ماند.
