# گزارش ارتقای SYSTEM v2.2.0 — هویت یکپارچهٔ Quest و مرز فرمان Daily Quest

## خلاصهٔ اجرایی

در این نسخه یک گام معماری واقعی انجام شد: هویت‌های ذخیره‌شدهٔ Quest میان لایهٔ فرمان و برنامه‌ریز مهاجرت همسان‌تر شده‌اند، منطق کاربردی Daily Quest از DOM جدا شده و شرط دریافت Daily Prize درون تراکنش IndexedDB دقیق‌تر شده است. **مسیر قدیمی رابط هنوز به IndexedDB منتقل نشده است.** این تصمیم عمدی است، چون آزمون واقعی مرورگر در محیط فعلی قبل از اجرای صفحه توسط سیاست Chromium مسدود می‌شود.

## تغییرهای پیاده‌سازی‌شده

### 1. قرارداد یکسان برای شناسهٔ Quest

- تابع `getCanonicalDomainQuestId()` در TypeScript منبع مشترک شناسه‌های ذخیره‌شدهٔ Daily، AI Daily، Custom، Boss و Goal است.
- شناسه‌های جدید Daily به قالب `daily-quest:<sourceId>:<YYYY-MM-DD>` و AI Daily به قالب `ai-daily-quest:<sourceId>:<YYYY-MM-DD>` تبدیل می‌شوند.
- شناسه‌های جدید Custom و Boss با قرارداد runtime همسان شده‌اند؛ Goal و Goal-evidence نیز به یک شناسهٔ Goal مشترک می‌رسند.
- شناسهٔ بیش‌ازحد بلند به‌جای کوتاه‌شدن خاموش رد می‌شود تا دو شناسهٔ متفاوت با truncation به یک رکورد برخورد نکنند.
- برای پایگاه‌های قدیمی، aliasهای فقط‌خواندنی تعریف شده‌اند. سرویس Daily/AI Daily فقط وقتی شناسهٔ قدیمی را می‌پذیرد که provenance مهاجرت با نوع و شناسهٔ منبع همخوان باشد.

### 2. کاتالوگ مشترک

شش Daily Quest اصلی و سه Boss Quest از تعریف محلی برنامه‌ریز مهاجرت به `src/data/quest-catalog.ts` منتقل شده‌اند. مهاجرت و سرویس کاربردی از همان کاتالوگ استفاده می‌کنند؛ در نتیجه خطر واگرایی شناسه‌ها و مشخصات پایه کاهش یافته است.

### 3. سرویس کاربردی مستقل Daily Quest

فایل `src/features/daily-quest-command.ts` اضافه شد. این سرویس:

- به `window`، `document` یا `localStorage` وابستگی ندارد.
- شناسهٔ canonical و aliasهای مجاز قدیمی را resolve می‌کند.
- XP و Coins را از رکورد ذخیره‌شدهٔ Quest می‌گیرد، نه از مقادیر ساختگی ارسال‌شده توسط UI.
- شناسهٔ تاریخچه را از قرارداد یکپارچهٔ TypeScript می‌سازد.
- ثبت Stat، شمارنده، تاریخچه و پاداش را از مسیر تراکنش واحد IndexedDB عبور می‌دهد.
- در صورت نبود Quest، Stat نامعتبر یا دادهٔ مهاجرتی بدون provenance صحیح، fail-closed عمل می‌کند.

این ماژول عمداً هنوز به دکمه‌های زنده وصل نشده است. منطق ضریب Streak در کنترل‌گر قدیمی وجود دارد و باید پیش از cutover، به‌صورت یک تغییر دامنه‌ای حسابرسی‌پذیر و با آزمون رگرسیون به مسیر TypeScript منتقل شود.

### 4. محافظت اتمیک Daily Prize

اکنون فرمانی که می‌خواهد Daily Prize را ثبت کند، باید شناسهٔ دقیق شش مأموریت اصلی و همان تاریخ محلی را تحویل دهد. تراکنش:

- وجود هر شش Quest را بررسی می‌کند؛
- اجازه نمی‌دهد Quest جاری خارج از فهرست شش‌تایی باشد؛
- وضعیت پنج Quest دیگر را با `completedQuestIds` بازیکن، رویداد تعبیه‌شدهٔ XP و دفتر XP پایدار مقایسه می‌کند؛
- در صورت ناسازگاری داده‌ها یا تکمیل‌نشدن مأموریت‌ها، کل تراکنش و پاداش را رد می‌کند؛
- تکمیل Quest نهایی و دریافت جایزه را در همان تراکنش نگه می‌دارد تا جایزهٔ تکراری ایجاد نشود.

### 5. حفظ سازگاری و داده‌ها

- مهاجرت همچنان opt-in است؛ کلیدهای ذخیرهٔ قدیمی localStorage حذف یا بازنویسی نمی‌شوند.
- مسیر زندهٔ ذخیره‌سازی هنوز localStorage است؛ هیچ cutover خودکاری در این نسخه فعال نشده است.
- هر 11 تم موجود حفظ شده‌اند.
- CSS تولیدی از شیت‌های منبع ساخته شده و فایل تولیدی مستقیماً ویرایش نشده است.
- Service Worker و دارایی‌های Android از منبع همین نسخه بازسازی می‌شوند.

## آزمون‌ها و راستی‌آزمایی

### آزمون‌هایی که اجرا و موفق شدند

- `npm test` — موفق؛ ساخت TypeScript و runtime، CSS، Service Worker، آزمون‌های TypeScript، تست‌های static و regression اجرا شدند.
- آزمون‌های progression و reward identity — موفق.
- آزمون‌های migration — موفق؛ بررسی شناسه‌های canonical و جلوگیری از پرداخت دوبارهٔ Questهای واردشده.
- آزمون سرویس Daily Quest — موفق، 22 بررسی شامل canonical/legacy IDs، provenance، منبع معتبر پاداش، تفکیک AI Daily، Stat/Skill metadata، شرط پاداش روزانه و ورودی نامعتبر.
- آزمون‌های progression math (1531)، smoke/unit (251)، parser، storage، security/build audit، skill progression (1335 روی 583 گره)، UI، Rewards، Profiles و تم‌ها — موفق.
- قراردادهای static تراکنش و Daily Prize gate — موفق.
- `node --check tests/browser/indexeddb-transaction-test.js` — موفق؛ فایل آزمون مرورگر از نظر نحو JavaScript معتبر است.
- `npm run prepare:android` — موفق؛ ساخت وب دوباره اجرا شد و 130 فایل با حجم حدود 5.98 MiB به assets اندروید همگام شد. این مرحله APK تولید نمی‌کند.
- نگه‌داری 11 تم و تولید Service Worker — در آزمون‌های خود پروژه تأیید شد.

### آزمون‌هایی که هنوز موفقیت آن‌ها تأیید نشده

- `npm run test:browser-idb`: محیط مدیریت‌شدهٔ Chromium صفحهٔ آزمایشی محلی را پیش از اجرای آن مسدود می‌کند. بنابراین هیچ نتیجهٔ واقعی IndexedDB از مرورگر تولید نشده و این آزمون را موفق گزارش نمی‌کنیم. آزمون‌های unit/contract جایگزین آزمون واقعی مرورگر نیستند.
- APK واقعی روی دستگاه Android در این کار ساخته یا آزمایش نشده است؛ فقط دارایی‌های وب به پروژهٔ Android کپی شدند.

## محدودیت‌های باقی‌مانده و معیار cutover

1. آزمون IndexedDB واقعی باید در محیطی اجرا شود که دسترسی مرورگر به صفحهٔ محلی را مسدود نکند؛ باید schema upgrade، تکمیل هم‌زمان، rollback، aliasهای مهاجرت، Daily Prize gate و replay بررسی شوند.
2. ضریب Streak در مسیر TypeScript باید حسابرسی‌پذیر و هم‌رفتار با کنترل‌گر فعلی مدل شود؛ نباید Quest ذخیره‌شده برای اعمال ضریب دائمی تغییر کند یا XP مهارت/Stat ناخواسته دو بار شمرده شود.
3. پس از موفقیت این آزمون‌ها، Daily Quest به‌تنهایی به UI متصل می‌شود. سپس عملکرد واقعی و حفظ ذخیره‌های قدیمی بررسی می‌شود؛ بعد از آن می‌توان سراغ AI Daily، Custom، Boss، Goals و Rewards رفت.
4. تا پایان این معیارها، localStorage منبع معتبر رابط زنده باقی می‌ماند.

**نتیجه:** v2.2.0 مرز معماری و محافظ‌های هویت را محکم‌تر کرده، اما هنوز ادعا نمی‌کند که UI زنده به IndexedDB منتقل شده یا آزمون واقعی مرورگر/APK موفق بوده است.
