# گزارش ارتقای SYSTEM v2.8.0 — Typed Custom & Boss Quest Rules

## خلاصه

در این نسخه، یک مرحلهٔ واقعی دیگر از مهاجرت معماری اجرا شد: منطق کاتالوگ و شرایط Boss Quest و بخش مهمی از قرارداد داده‌های Custom Quest از کنترل‌گر JavaScript قدیمی به ماژول مستقل TypeScript انتقال یافت. این تغییر مرحله‌ای است؛ رابط و آداپتور ذخیره‌سازی قدیمی باقی مانده‌اند تا کلیدها و داده‌های کاربران بدون نیاز تغییر حفظ شوند.

## تغییرات پیاده‌سازی‌شده

- فایل تازهٔ `src/features/quest-command.ts` ساخته شد. این ماژول مستقل از DOM و ذخیره‌سازی است و نرمال‌سازی سوابق Custom Quest، اعتبارسنجی ساخت مأموریت جدید، بررسی وضعیت تکمیل و ارزیابی Boss Quest را مدیریت می‌کند.
- `src/data/quest-catalog.ts` اکنون منبع واحد تعریف Boss Questها، متن توضیح/شرط، جایزه‌ها و معیارهای بازشدن است. کنترل‌گر دیگر فهرست جداگانه‌ای با همان شناسه‌ها و شرط‌ها نگه نمی‌دارد.
- `js/app.js` پیش از بارگذاری اسکریپت‌های قدیمی، API محدود و منجمدشدهٔ `SYSTEMTypeScriptQuestDomain` را منتشر می‌کند.
- `js/legacy/app-controller.js` وضعیت جاری را به تابع TypeScript می‌دهد و نتیجه را نمایش می‌دهد؛ اعتبارسنجی ایجاد Custom Quest و جلوگیری از تکمیل تکراری نیز از قرارداد TypeScript استفاده می‌کنند.
- نرمال‌سازی ذخیره‌های قدیمی شناسه‌های پایدار و فیلدهای اضافی ناشناخته را حفظ می‌کند، شناسه‌های تکراری را فیلتر می‌کند، مقدارهای نامعتبر را محدود می‌کند و سقف ۱۰۰۰ مأموریت را نگه می‌دارد.
- آزمون‌های جدید شامل ۴۱ بررسی مشخص برای داده‌های قدیمی، شناسه‌ها، محدودهٔ XP و Coins، پیوند Goal، تاریخ ساخت، تکمیل تکراری و سه شرط Boss است.
- نگهبان معماری و آزمون موجود Goal به‌روزرسانی شدند تا مرز جدید TypeScript بررسی شود.

## سازگاری و نگه‌داری اطلاعات

کلیدهای موجود از جمله `system_v2_custom_quests` و `system_v2_boss_completed` تغییر نکرده‌اند. شکل اصلی ذخیرهٔ کاربران و روش فعلی ثبت XP/Coins نیز در این نسخه تغییر عمده نکرده است. عملیات نوشتن همچنان از آداپتور قدیمی و تراکنش rollback موجود استفاده می‌کند.

## نتیجهٔ ساخت و آزمون‌ها

فرمان‌های زیر با موفقیت اجرا شدند:

- `npm test` — ساخت و مجموعهٔ آزمون‌های TypeScript، static/regression و architecture موفق شدند.
- `npm run doctor` — نسخه، فایل‌های اصلی و نگهبان معماری معتبر بودند.
- `npm run prepare:android` — فایل‌های وب ساخته و ۱۳۵ فایل، حدود ۶٫۰۱ MiB، به دارایی‌های Android همگام شدند.
- کامپایل TypeScript — موفق.

## مواردی که هنوز کامل نشده‌اند

- وابستگی `@playwright/test` در محیط موجود نصب نیست؛ آزمون تعاملی Playwright در این نوبت اجرا نشد.
- آزمون واقعی IndexedDB در مرورگر در این نوبت اجرا نشد؛ بنابراین هیچ مجوزی برای تبدیل IndexedDB به منبع فعال UI به‌دست نیامده است.
- APK باینری ساخته نشد. همگام‌سازی Web assets با ساخت Gradle و آزمون نصب APK فرق دارد.
- `js/legacy/app-controller.js` هنوز بزرگ است. هماهنگی UI، Goal evidence، اجرای پاداش‌های Custom/Boss و مسیرهای ذخیره‌سازی قدیمی باید به‌تدریج با آزمون‌های رگرسیون جدا شوند.
- SQLite، Kotlin، Python runtime، سرور AI، Canvas/WebGL، Rust/WASM و ICU MessageFormat به‌صورت نمایشی اضافه نشدند؛ هر کدام تنها وقتی وارد runtime می‌شوند که نیاز و دروازهٔ آزمون روشن باشد.

## قدم بعدی

مرحلهٔ بعدی باید استخراج هماهنگی اجرای پاداش Custom/Boss و Goal evidence به فرمان‌های مستقل آزمون‌پذیر باشد، بدون جابه‌جایی ناگهانی ذخیره‌سازی. به‌صورت جداگانه، CI باید آزمون واقعی IndexedDB را در مرورگری مجاز اجرا کند. فقط پس از موفقیت آزمون، بررسی recovery و rollback و مقایسهٔ داده‌ها می‌توان انتقال محدود را پیشنهاد کرد.
