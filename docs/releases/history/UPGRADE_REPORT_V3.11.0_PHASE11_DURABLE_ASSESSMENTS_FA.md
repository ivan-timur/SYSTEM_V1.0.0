# گزارش ارتقای SYSTEM v3.11.0 — فاز یازدهم: تاریخچهٔ پایدار ارزیابی

## هدف
فراهم‌کردن ذخیره‌سازی پایدار و قابل اعتبارسنجی برای تلاش‌های آزمون مهارت، بدون صدور پاداش از لایهٔ ارزیابی.

## تغییرات پیاده‌سازی‌شده
- نسخهٔ پایگاه دادهٔ IndexedDB از ۴ به ۵ ارتقا یافت.
- فروشگاه `assessment_attempts` با کلید اصلی یکتای `attemptId` و نمایه‌های `assessedAt` و `assessmentId` اضافه شد.
- API نوع‌دار `saveSkillAssessmentAttempt` داده‌ها را اعتبارسنجی می‌کند و تلاش تکراری با همان شناسه را بازنویسی نمی‌کند.
- API نوع‌دار `listSkillAssessmentAttempts` تاریخچه را از جدیدترین به قدیمی‌ترین برمی‌گرداند.
- رکوردها باید `rewardIssued: false` داشته باشند؛ این API هیچ XP، سکه یا پاداشی صادر نمی‌کند.
- فروشگاه‌های قبلی حفظ می‌شوند و ارتقا از مسیر استاندارد `onupgradeneeded` انجام می‌شود.
- نسخه، CHANGELOG و گزارش انتشار به 3.11.0 همگام شدند.

## اعتبارسنجی انجام‌شده
- ساخت کامل پروژه با `npm run build` موفق شد.
- کل خط آزمون `npm test` با موفقیت پایان یافت؛ شامل آزمون‌های TypeScript، آزمون‌های ایستا و کنترل معماری.
- آزمون موتور ارزیابی مهارت با ۷ assertion موفق اجرا شد.
- آزمون‌های Playwright واقعی و اجرای روی دستگاه در این مرحله اجرا نشدند.

## محدودیت‌ها
- این فاز API ذخیره‌سازی پایدار را آماده کرده، اما فرم قدیمی «ردیاب تسلط» در رابط کاربری هنوز به API جدید IndexedDB متصل نشده است؛ UI فعلی از localStorage استفاده می‌کند. بنابراین تاریخچهٔ فرم موجود هنوز از فروشگاه جدید خوانده/نوشته نمی‌شود.
- آزمون مرورگر واقعی برای ارتقای IndexedDB، کل خط آزمون `npm test`، Playwright، ساخت APK و آزمایش روی دستگاه در این اجرا انجام نشده‌اند.
- نتیجهٔ آزمون یا نمرهٔ خوداظهاری به‌تنهایی اثبات مستقل تسلط نیست.
