# گزارش ارتقای SYSTEM v3.3.0 — فاز سوم

## هدف
ایجاد یک قرارداد دامنه‌ای قابل‌آزمون برای اتصال منطقی مسیر رشد:

**Goal → Milestones → Skills → Quests → Evidence → Evaluation → (سپس مسیر پاداش مرکزی)**

این فاز روی نسخهٔ تأییدشدهٔ `v3.2.2` ساخته شده و رابط کاربری موجود را بازطراحی نکرده است.

## تغییرات اصلی

### ۱. موتور ارزیابی مسیر هدف
فایل جدید `src/features/goal-curriculum.ts` یک ماژول TypeScript خالص اضافه می‌کند که:
- هویت Goal، Milestone، Evidence و Quest را اعتبارسنجی می‌کند.
- شناسهٔ تکراری milestone/evidence و ثبت دوبارهٔ یک Quest برای همان milestone را رد می‌کند.
- ارجاع prerequisite ناموجود، وابستگی به خود و چرخه‌های بین milestoneها را رد می‌کند.
- تعداد شواهد موردنیاز را محدود و اعتبار زمان، Stat و شناسهٔ Skill را بررسی می‌کند.
- milestoneها را مستقل از ترتیب آرایه و بر اساس وابستگی‌هایشان ارزیابی می‌کند.
- فقط شواهدی را حساب می‌کند که `passed: true` داشته باشند؛ فعالیت عادی به‌تنهایی تسلط Skill محسوب نمی‌شود.
- الزام‌های Skill را جدا از شمارش شواهد بررسی می‌کند.
- وضعیت قفل/بازبودن، پیشرفت milestoneها، درصد پیشرفت Goal و آمادگی تکمیل را برمی‌گرداند.

### ۲. جلوگیری از پاداش ناخواسته
تابع ارزیابی فقط نتیجهٔ محاسبه را برمی‌گرداند و `rewardIssued: false` دارد. این ماژول به‌تنهایی XP، Coin یا پاداش نمی‌دهد و چیزی در Storage نمی‌نویسد. مسیرهای فعلی تراکنش و پاداش مرکزی همچنان مرجع پرداخت باقی می‌مانند.

### ۳. اتصال کنترل‌شده به برنامه
API دامنه‌ای از طریق `window.SYSTEMGoalCurriculum.validate()` و `window.SYSTEMGoalCurriculum.evaluate()` در ورودی برنامه در دسترس قرار گرفت تا آداپتر Goal بتواند در فاز بعدی به‌صورت کنترل‌شده از آن استفاده کند.

### ۴. آزمون‌ها و انتشار
- ۱۹ assertion جدید برای مسیر Goal Curriculum اضافه شد.
- نسخه به `3.3.0` ارتقا یافت و متادیتای نسخه با اسکریپت رسمی همگام شد.
- فایل‌های TypeScript، runtime، CSS و Service Worker بازسازی شدند.
- Service Worker تعداد ۱۴۱ منبع هم‌مبدأ را precache می‌کند.
- نسخهٔ وب به دارایی‌های Android همگام شد: ۱۴۰ فایل، حدود ۶٫۰۷ MiB.

## نتایج آزمون
- `npm test` — موفق؛ آزمون‌های TypeScript، آزمون‌های ایستا، رگرسیون‌های پروژه و معماری عبور کردند.
- `npm run doctor` — موفق؛ فایل‌های runtime و متادیتای نسخه سازگارند.
- `npm run prepare:android` — موفق؛ خروجی وب در دارایی‌های Android همگام شد.
- CSS: ۶۴ فایل منبع؛ صفر `!important` در خروجی runtime.

## مرزهای مهم این فاز
- هنوز رابط کاربری جدیدی برای ساخت/ویرایش milestoneها اضافه نشده است.
- این موتور هنوز جایگزین کامل منطق قدیمی `SYSTEMGoalProgress.recordEvidence` در آداپتر قدیمی نشده؛ فعلاً به‌عنوان قرارداد typed و API قابل‌آزمون اضافه شده است. بنابراین داده‌های ذخیره‌شدهٔ فعلی به‌طور خودکار تغییر شکل نمی‌دهند.
- مرورگر واقعی و Playwright اجرا نشد؛ وابستگی Playwright در محیط حاضر نصب نبود.
- APK ساخته یا روی دستگاه واقعی آزمایش نشده است؛ فقط دارایی‌های وب Android همگام شده‌اند.
- SQLite، سرور AI و همگام‌سازی ابری در این فاز پیاده‌سازی نشده‌اند.

## گام بعدی پیشنهادی
فاز چهارم باید قرارداد جدید را با آداپتر Goal و Roadmap موجود یکپارچه کند، با مهاجرت سازگار و بدون تخریب داده‌های قدیمی؛ سپس رابط milestone/evidence، آزمون مرورگر واقعی و بررسی حالت آفلاین اضافه شود.
