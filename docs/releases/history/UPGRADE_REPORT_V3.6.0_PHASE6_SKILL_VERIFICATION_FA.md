# گزارش ارتقای SYSTEM v3.6.0 — فاز ششم: اثبات مهارت و پیشرفت معتبر

## هدف
تفکیک «انجام مأموریت» از «اثبات مهارت». اختصاص یک `skillId` به Quest به‌تنهایی دیگر برای تکمیل مهارت موردنیاز در ارزیابی Curriculum کافی نیست.

## تغییرات
- افزودن قرارداد `SkillVerification` شامل روش بررسی (`assessment`، `project-review` یا `manual-check`)، زمان بررسی و نمرهٔ ۰ تا ۱۰۰.
- اعتبارسنجی روش، زمان، نمره و الزام وجود شناسهٔ Skill در صورت ارائهٔ رکورد تأیید.
- احتساب Skill به‌عنوان تأییدشده فقط هنگامی که شواهد مأموریت موفق باشد، شناسهٔ Skill وجود داشته باشد و نمرهٔ تأیید حداقل ۸۰ از ۱۰۰ باشد.
- حفظ جدایی مسئولیت‌ها: ارزیاب همچنان فقط محاسبه می‌کند؛ داده ذخیره نمی‌کند و XP/Coin اعطا نمی‌کند.
- حفظ مسیر سازگاری Goalهای قدیمی؛ شواهد legacy به مهارت تأییدشده تبدیل نمی‌شوند و چون مسیر قدیمی الزام Skill تعریف نمی‌کند، رفتار قبلی هدف‌ها تغییر نمی‌کند.
- افزودن آزمون‌های اختصاصی برای حد آستانه، شناسهٔ مهارت، روش نامعتبر، تاریخ نامعتبر و نمرهٔ خارج از محدوده.

## محدودیت‌های مهم
- این فاز قرارداد داده و ارزیابی را محکم‌تر می‌کند؛ هنوز رابط کاربری برای اجرای آزمون مهارت، ارسال پروژه برای بررسی یا ثبت تأیید مربی اضافه نشده است.
- `skillVerification` یک رکورد داده است؛ این نسخه به‌تنهایی هویت تأییدکننده را احراز نمی‌کند و برای محیط چندکاربره/آنلاین به لایهٔ مجوزدهی و سرور معتبر نیاز است.
- آزمون‌های Playwright/E2E، ساخت APK و آزمایش روی دستگاه واقعی فقط در صورت اجرای جداگانه گزارش خواهند شد؛ موفقیت آزمون‌های Node/TypeScript معادل آزمون واقعی Android نیست.
