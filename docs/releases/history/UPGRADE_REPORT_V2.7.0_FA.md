# گزارش ارتقای SYSTEM v2.7.0 — Typed Daily Quest State Boundary

## خلاصه

در این نسخه، یک بخش مشخص از منطق Quest از کنترل‌گر قدیمی استخراج شد: قرارداد خواندن و نرمال‌سازی وضعیت تکمیل Daily Quest و ساخت داده‌های ذخیره‌سازی آن. تغییرات به شکل مرحله‌ای انجام شد؛ کلیدهای قدیمی و آداپتور ذخیره‌سازی موجود حفظ شده‌اند.

## تغییرات واقعی

- ماژول جدید `src/storage/legacy-daily-quest-state.ts` مالک تاریخ‌بندی، نرمال‌سازی payload، فیلتر نوع مقادیر و ساخت رکوردهای ذخیره‌سازی است.
- `js/app.js` API تایپ‌شده را پیش از بارگذاری کنترل‌گر قدیمی منتشر می‌کند.
- `js/legacy/app-controller.js` دیگر JSON مربوط به وضعیت Daily Quest را مستقلاً parse و فیلتر نمی‌کند؛ اکنون به قرارداد TypeScript مراجعه می‌کند و عملیات ذخیره را از مسیر `SYSTEMStorage.applyEntriesAtomically` نگه می‌دارد.
- کلیدهای `system_v2_quests` و `system_v2_quest_date`، ساختار ذخیرهٔ قدیمی و رفتار reset روزانه حفظ شده‌اند.
- آزمون‌های اختصاصی برای همان روز، تغییر روز، JSON خراب، مقادیر نامعتبر، شناسه‌های آینده، تاریخ/کلید نامعتبر و سریال‌سازی افزوده شد.
- نگهبان معماری اکنون وجود این مرز TypeScript و استفادهٔ کنترل‌گر از آن را بررسی می‌کند.
- آماده‌سازی Android با موفقیت انجام شد: ۱۳۴ فایل وب، حدود ۶٫۰۰ MiB، به دارایی‌های Android همگام شدند. APK باینری در این مرحله ساخته نشده است.

## آزمون‌ها و اعتبارسنجی

`npm test` در این محیط اجرا شد و کل زنجیرهٔ build، آزمون‌های TypeScript، آزمون‌های static/regression و معماری موفق شدند.

`npm run test:browser-idb` نیز اجرا شد، اما نتیجهٔ تست مرورگر تولید نشد: سیاست مدیریتی Chromium در این محیط `URLBlocklist: ["*"]` دارد و ناوبری localhost را با `ERR_BLOCKED_BY_ADMINISTRATOR` رد می‌کند. هیچ سیاست مرورگری تغییر داده نشد و این تست موفق گزارش نشده است.

## محدوده و ریسک باقی‌مانده

- این تغییر **انتقال به IndexedDB نیست**؛ `localStorage` همچنان منبع واقعی رابط است.
- عملیات Quest دیگر در کنترل‌گر زیاد است؛ نسخهٔ بعدی باید بخش‌بخش سایر مسیرهای Daily/AI/Custom/Boss/Goal را از UI orchestration جدا کند.
- ساخت دارایی‌های وب برای Android با ساخت APK یکسان نیست. این گزارش APK کامپایل‌شده را ادعا نمی‌کند.

## قدم بعدی

۱. اجرای آزمون تراکنش‌های واقعی IndexedDB در CI یا مرورگری که مجاز به بازکردن localhost باشد.
۲. استخراج command orchestration برای AI Daily و Custom Quest با مرزهای آزمون‌شده.
۳. سپس بررسی cutover محدود و قابل rollback، فقط پس از موفقیت تست مرورگر و مسیر بازیابی.
