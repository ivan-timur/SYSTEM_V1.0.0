# گزارش ارتقا — SYSTEM v3.21.0
## فاز ۲۲: تکمیل چرخهٔ یادگیری

### تغییرات اجراشده
- موتور TypeScript مسیر تطبیقی به نقطهٔ ورود برنامه متصل شد و از طریق API فقط‌خواندنی در اختیار رابط کاربری قرار گرفت.
- پنل مسیر یادگیری در صفحهٔ Quest اضافه شد؛ پیشنهادها از هدف‌های ذخیره‌شده، مأموریت‌های سفارشی، ارزیابی‌های مهارت و وضعیت تکمیل ساخته می‌شوند.
- انتخاب مهارت بر اساس شناسهٔ ثبت‌شده در ارزیابی انجام می‌شود؛ اگر رابطهٔ قابل‌اعتماد مهارت و مأموریت موجود نباشد، سیستم حدس نمی‌زند و پیام راهنما نشان می‌دهد.
- وضعیت تأیید مهارت از قرارداد آمادگی `SYSTEMSkillMastery` گرفته می‌شود؛ یک امتیاز یا تکمیل مأموریت به‌تنهایی تسلط را اثبات نمی‌کند.
- هدف فعال و مسیر نقاط عطف با `SYSTEMGoalProgress.evaluateLegacyCurriculum` محاسبه و درصد پیشرفت و شواهد نمایش داده می‌شوند.
- دکمهٔ پیشنهاد، مأموریت موجود را در صفحه پیدا کرده و به آن اسکرول می‌کند.
- موتور پیشنهاددهی XP، Coins یا تأیید مهارت صادر نمی‌کند؛ ثبت شواهد و پاداش‌ها همچنان تحت کنترل مسیرهای اصلی موجود است.
- استایل واکنش‌گرا و پشتیبانی از `prefers-reduced-motion` افزوده شد.

### آزمون‌ها
- آزمون قرارداد اتصال UI افزوده شد تا وجود اتصال موتور، خواندن داده‌های واقعی، ارزیابی نقاط عطف، عدم صدور پاداش، ایمنی DOM و سبک موبایل بررسی شود.
- آزمون‌های قبلی موتور مسیر تطبیقی و ارزیابی برنامهٔ هدف حفظ شدند.
- آزمون مرورگر واقعی Playwright و آزمون روی دستگاه فیزیکی بخشی از این فاز نیستند و باید در فاز ۲۳ و ۲۴ انجام شوند.

### محدودیت‌های شناخته‌شده
- مأموریت‌های روزانه تنها زمانی وارد پیشنهادها می‌شوند که شناسهٔ مهارت معتبر از سوابق ارزیابی قابل اتصال باشد. این رفتار محافظه‌کارانه عمداً از ساختن پیوندهای ساختگی جلوگیری می‌کند.
- مدل قدیمی Goal به شکل سازگار به نقاط عطف ترتیبی تبدیل می‌شود؛ این فاز ساختار دادهٔ ذخیره‌شده را خودکار مهاجرت نمی‌دهد.
