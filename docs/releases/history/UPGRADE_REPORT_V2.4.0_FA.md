# گزارش ارتقای SYSTEM v2.4.0 — دروازهٔ واقعی آزمون IndexedDB

## خلاصهٔ اجرایی

این نسخه به مشکل آزمون مرورگر در سطح پروژه رسیدگی می‌کند، بدون آن‌که سیاست امنیتی محیط را دور بزند. ریشهٔ مشکل در این محیط بررسی شد: Chromium مدیریت‌شده، URL محلی آزمون را پیش از اجرای JavaScript صفحه مسدود می‌کند. اجراکنندهٔ آزمون اکنون دلیل قابل‌مشاهده‌تری برای این وضعیت می‌دهد، در CI از مرورگر Playwright نصب‌شده استفاده می‌کند، و آزمون واقعی IndexedDB به دروازه‌های CI کیفیت و انتشار اضافه شده است.

**نکتهٔ شفاف:** آزمون واقعی IndexedDB در همین محیط هنوز قابل اجرا نیست؛ سیاست مدیریتی فعال است. نسخهٔ 2.4.0 این مانع محیطی را تشخیص می‌دهد و مسیر خودکار اجرای همان آزمون در runner مجاز CI را فراهم می‌کند، اما تا زمان اجرای موفق CI نباید نتیجهٔ مرورگر واقعی را «موفق» تلقی کرد. UI اصلی همچنان `localStorage` را منبع معتبر نگه می‌دارد و cutover زنده به IndexedDB انجام نشده است.

## علت فنی تأییدشده

آزمون `npm run test:browser-idb` صفحه‌ای مانند زیر را از سرور HTTP محلی باز می‌کند:

`http://127.0.0.1:<port>/tests/browser/indexeddb-transaction-test.html`

در اجرای واقعی، CDP توانست به Chromium متصل شود و درخواست `Page.navigate` را ارسال کند؛ پاسخ مرورگر شامل `net::ERR_BLOCKED_BY_ADMINISTRATOR` بود. هیچ نتیجه‌ای از کد آزمون IndexedDB برنگشت.

بررسی فقط‌خواندنی فایل‌های سیاست نشان داد:

- `/etc/chromium/policies/managed/000_policy_merge.json` شامل `URLBlocklist: ["*"]` است.
- `/usr/local/chromium/policies/managed/001_base_url_blocklist.json` نیز شامل `URLBlocklist: ["*"]` است.

این سیاست مدیریتی بیرون از کد پروژه قرار دارد. اصلاح TypeScript، تغییر در IndexedDB یا تغییر فایل آزمون نمی‌تواند اجازهٔ مرورگر را به‌طور مشروع ایجاد کند؛ فقط مدیر محیط یا یک runner مجاز می‌تواند مسیر آزمون را فراهم کند. اجراکنندهٔ SYSTEM عمداً سیاست مرورگر را حذف یا غیرفعال نمی‌کند.

## تغییرهای v2.4.0

### ۱. Playwright-first برای آزمون واقعی مرورگر

`tests/run-indexeddb-browser-test.js` اکنون ابتدا `@playwright/test` و مرورگر نصب‌شدهٔ آن را انتخاب می‌کند. این مسیر، مسیر اصلی CI است. اگر Playwright نصب نشده باشد، اجرای مبتنی بر CDP و Chromium سیستم به‌عنوان fallback حفظ شده است.

مسیر Playwright دارای timeout محدود برای بازکردن صفحه و انتظار برای نتیجه، دریافت `pageerror` و بررسی صریح وضعیت `passed` یا `failed` است. خطاهای مرورگر یا پایان‌نیافتن صفحه به نتیجهٔ موفق تبدیل نمی‌شوند.

### ۲. تشخیص سیاست مدیریتی بدون تغییر آن

هنگام دریافت `ERR_BLOCKED_BY_ADMINISTRATOR`، اجراکننده فایل‌های سیاست شناخته‌شده را فقط می‌خواند و در صورت یافتن `URLBlocklist: ["*"]` مسیر فایل را گزارش می‌کند. هیچ فایل سیستمی تغییر نمی‌کند، هیچ سیاستی غیرفعال نمی‌شود و هیچ آزمون مسدودشده‌ای موفق اعلام نمی‌شود.

### ۳. اتصال آزمون به CI واقعی

دو workflow زیر پس از نصب Chromium توسط Playwright، آزمون واقعی تراکنش‌های IndexedDB را اجرا می‌کنند:

- `.github/workflows/quality.yml`
- `.github/workflows/release-android.yml`

ترتیب انتشار طوری تنظیم شده که آزمون IndexedDB پیش از آزمون‌های UI و قبل از بسته‌بندی/انتشار Android اجرا شود. اگر آزمون شکست بخورد، job مربوط به CI/انتشار شکست می‌خورد و انتشار نباید ادامه پیدا کند.

### ۴. تقویت آزمون‌های قراردادی پروژه

آزمون‌های runner و pipeline اکنون وجود مسیر Playwright در runner و اجرای `npm run test:browser-idb` در workflowهای کیفیت و انتشار را بررسی می‌کنند. این آزمون‌ها صرفاً صحت پیکربندی را می‌سنجند؛ آن‌ها جایگزین IndexedDB واقعی نیستند.

### ۵. حفظ رفتار محصول و داده‌ها

- ۱۱ تم فعلی دست‌نخورده باقی مانده‌اند.
- schema IndexedDB و مسیر مهاجرت داده‌ها در این نسخه تغییر ماهوی نکرده‌اند.
- ذخیره‌های قبلی `localStorage` حذف نمی‌شوند.
- هیچ دکمهٔ زندهٔ Daily Quest به IndexedDB منتقل نشده است.

## اجرای آزمون در محیط مجاز

پس از دریافت پروژه در یک محیط توسعه یا runner که اجازهٔ صفحات HTTP محلی را دارد، این دستورات را اجرا کنید:

```bash
npm install --no-audit --no-fund
npx playwright install chromium
npm run test:browser-idb
```

در مخزن متصل به GitHub، workflow کیفیت با push/pull request یا از طریق `workflow_dispatch` همین آزمون را پس از نصب Chromium اجرا می‌کند. نتیجهٔ سبز آن workflow، مدرک لازم برای عبور از این دروازه است. این بسته به‌تنهایی نمی‌تواند سیاست مدیریتی runtime فعلی را تغییر دهد.

## معیار نسخهٔ بعد

فقط پس از مشاهدهٔ اجرای موفق واقعی آزمون IndexedDB در CI یا runner مجاز، باید مسیر زندهٔ Daily Quest به ذخیره‌سازی IndexedDB منتقل شود. پس از انتقال محدود، باید ذخیره‌های قدیمی، XP، Level، Coins، Stat/Skill، Streak، Daily Prize، rollback و جلوگیری از پرداخت تکراری روی رابط واقعی دوباره آزموده شوند. تا آن زمان، مسیر `localStorage` مرجع باقی می‌ماند.
