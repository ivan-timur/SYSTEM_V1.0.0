# گزارش مرحلهٔ چهارم — اصلاح ساختار ناوبری موبایل

## محدوده
این مرحله فقط روی یکپارچگی CSS ناوبری موبایل و همگام‌سازی فایل CSS اندروید تمرکز دارد. نسخهٔ برنامه عمداً روی `1.0.0` باقی مانده است.

## یافته و اصلاح
- قواعد ابعاد و چیدمان نوار ناوبری موبایل قبلاً هم در `mobile.css` و هم در `mobile-nav-integrity.css` تکرار می‌شدند؛ این وضعیت امکان اختلاف تدریجی بین دو تعریف را ایجاد می‌کرد.
- یک منبع نهایی و مشخص برای ناوبری موبایل در `mobile-nav-integrity.css` حفظ شد.
- محدودیت‌های اصلی اندازهٔ نوار کناری دسکتاپ به‌صورت صریح برای موبایل بازنشانی می‌شوند: `min-width: 0`، `height: auto`، `max-width: 100vw` و `max-height: none`.
- پنج مقصد ناوبری در ستون‌های هم‌اندازه نگه داشته می‌شوند؛ آیکون‌ها از تغییر شکل ناشی از transform ناوبری جلوگیری می‌کنند و اندازهٔ دستگاه‌های بسیار باریک نیز پوشش داده شده است.
- تست رگرسیون UI برای منبع واحد CSS و قرارداد ابعاد موبایل گسترش یافت.
- CSS تولیدشده با نسخهٔ موجود در بستهٔ Android همگام شد.

## اعتبارسنجی
- `npm run build:css` — موفق؛ ۶۷ منبع CSS، بدون `!important` در خروجی.
- `node tests/ui-layout-test.js` — موفق؛ ۲۹ بررسی.
- `node scripts/project-doctor.js` — موفق؛ Playwright نصب نیست و تست مرورگر واقعی اجرا نشده است.
- `node scripts/architecture-guard.js` — موفق.
- `npm run test:static` — موفق؛ همهٔ آزمون‌های ایستا، از جمله ۴۲ بررسی آمادگی Android، عبور کردند.

## محدودیت
به‌دلیل نصب نبودن وابستگی Playwright، آزمون بصری واقعی در مرورگر و آزمون روی دستگاه Android در این مرحله اجرا نشده است؛ بنابراین این گزارش موفقیت آزمون‌های ایستا را ثبت می‌کند و ادعای آزمون فیزیکی دستگاه ندارد.
