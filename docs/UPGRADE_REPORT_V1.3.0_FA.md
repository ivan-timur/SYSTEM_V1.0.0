# گزارش ارتقای SYSTEM v1.3.0 — Seed Contracts

## هدف این پله
این نسخه یک گام محدود و قابل‌آزمایش در معماری هدف است: داده‌های JSON بسته‌بندی‌شده (Quest، مهارت/Stat، Reward و پروفایل پیش‌فرض) اکنون اعتبارسنج TypeScript و آزمون قرارداد دارند، بدون اینکه شکل داده‌های فعلی یا رابط کاربری تغییر کند.

## تغییرات
- افزودن `src/data/seed-validation.ts` با اعتبارسنج‌های صریح برای چهار نوع seed.
- بررسی شناسه‌های تکراری، عنوان/نام خالی، XP و سکه منفی یا نامتناهی، سطح نامعتبر، مهارت تکراری و رتبه ناشناخته.
- افزودن تست‌هایی که فایل‌های واقعی JSON پروژه را می‌خوانند و همچنین ورودی‌های خراب نمونه را رد می‌کنند.
- افزایش نسخه به `1.3.0`.

## محدودیت آگاهانه
این پله هنوز JSON را به منبع runtime تبدیل نمی‌کند؛ فقط قرارداد داده را تعریف و بررسی می‌کند. اتصال به UI یا موتور Quest باید در پله‌ای جداگانه انجام شود تا رفتار فعلی برنامه ناخواسته تغییر نکند. موتور پیشرفت همچنان در `src/core/progression.ts` باقی می‌ماند و منطق XP نباید در Kotlin/Python/Rust دوباره پیاده‌سازی شود.

## معماری هدف
- TypeScript: منطق پیشرفت واحد و قراردادهای داده.
- IndexedDB فعلی: ذخیره‌سازی مرورگر؛ SQLite برای گزارش‌گیری یا لایه بومی فقط پس از تصمیم معماری و مهاجرت داده.
- JavaScript legacy: انتقال مرحله‌ای، با تست هر بخش پیش از حذف مسیر قدیمی.
- Kotlin: قابلیت‌های بومی اندروید؛ Java موجود تا زمان مهاجرت امن حفظ می‌شود.
- Python، WebGL/Canvas، Rust/WASM و Swift: فقط برای نیازهای مشخص و اندازه‌گیری‌شده، نه افزودن فناوری بدون ضرورت.

## تأیید
نتیجه آزمون باید از اجرای واقعی `npm test` در محیط ساخت به دست آید؛ این گزارش به‌تنهایی ادعای اجرای مرورگر یا APK واقعی نمی‌کند.
