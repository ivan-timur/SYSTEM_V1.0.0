# گزارش ارتقای SYSTEM به نسخه 3.4.0

تاریخ: ۱۳ اکتبر ۲۰۲۶

## تغییرات مهم

### ۱. ایمنی و بازیابی داده‌ها
- ماژول فعال `js/core/storage.js` اضافه شد.
- فایل پشتیبان نسخه ۲ با کنترل صحت برای تشخیص خرابی تصادفی ایجاد می‌شود؛ این checksum امضای رمزنگاری‌شده نیست.
- هنگام بازیابی، اندازه فایل، تعداد کلیدها، ساختار داده‌های شناخته‌شده و checksum بررسی می‌شوند.
- پشتیبان‌های معتبر نسخه ۱ همچنان قابل وارد کردن هستند.
- بازیابی کامل فقط کلیدهای متعلق به SYSTEM را جایگزین می‌کند و کلیدهای سایر برنامه‌های مرورگر را حذف نمی‌کند.
- پنل Storage Health برای یافتن JSON خراب و داده‌های ناسازگار با ساختار شناخته‌شده اضافه شد.

### ۲. قابل‌اعتمادتر شدن مأموریت و پاداش
- برای تکمیل مأموریت‌های روزانه و AI، مأموریت‌های سفارشی و Boss، دریافت پاداش، خرید فروشگاه، تکمیل هدف و پاداش ورود روزانه، سازوکار تراکنش و بازگردانی بهترین‌تلاش اضافه شد.
- شکست ذخیره‌سازی به منطق عملیات برگردانده می‌شود تا از باقی ماندن تغییرات ناقص جلوگیری شود.
- در صورت تغییر داده‌ها از یک تب دیگر، عملیات پاداش و پیشرفت تا بارگذاری دوباره تب متوقف می‌شوند.

### ۳. پروکسی اختیاری امن‌تر برای هوش مصنوعی
- سرور اختیاری `backend/server.mjs` با Node.js و بدون نیاز به نصب بسته npm اضافه شد.
- کلیدهای Groq و Gemini می‌توانند فقط در متغیرهای محیطی سرور نگهداری شوند.
- رابط **AI → Secure Proxy (removed in personal build)** در برنامه اضافه شد.
- سرور از توکن Bearer، فهرست مجاز Origin و مدل‌ها، محدودیت اندازه درخواست، بررسی ساختار پیام‌ها، محدودیت نرخ درخواست و timeout استفاده می‌کند.
- سرور به نشانی دلخواه کاربر درخواست نمی‌فرستد؛ Endpointهای ارائه‌دهنده ثابت هستند.
- این پروکسی برای استفاده شخصی یا کاربران مورد اعتماد طراحی شده است؛ هنوز سامانه کامل احراز هویت چندکاربره نیست.

### ۴. بهینه‌سازی فایل تصویری
- تصویر رتبه E از PNG با پسوند اشتباه `.webp` به WebP واقعی تبدیل شد.
- اندازه فایل از ۳٬۱۸۰٬۰۷۲ بایت به ۲۷۴٬۴۸۴ بایت کاهش یافت؛ حدود ۹۱٪ کوچک‌تر، همراه با حفظ شفافیت.
- فایل تصویری قدیمی و بدون ارجاع که با `.trashed` نام‌گذاری شده بود حذف شد.
- آزمون‌های منبع حالا مسیرهای `url(...)` در CSS و امضای واقعی فایل‌های WebP را هم بررسی می‌کنند.

## اجرای نسخه محلی

برای استفاده معمول، فایل `index.html` را باز کنید. اگر مرورگر به‌دلیل محدودیت فایل محلی از بارگذاری درست جلوگیری کرد، در پوشه پروژه اجرا کنید:

```bash
python -m http.server 8000
```

سپس `http://127.0.0.1:8000` را باز کنید. این روش برای قابلیت‌های اصلی به Backend نیاز ندارد.

## نتیجه آزمون‌های خودکار

- `node tests/smoke-test.js`: موفق، ۱۷۴ بررسی؛ ۲۱ فایل JSON معتبر.
- `node tests/storage-test.js`: موفق، ۲۰ بررسی.
- `node --test backend/server.test.mjs`: موفق، ۹ تست HTTP با پاسخ ساختگی ارائه‌دهنده.
- بررسی Syntax فایل‌های اصلی و سرور موفق.

تست‌های پروکسی از پاسخ ساختگی استفاده می‌کنند؛ هیچ درخواست واقعی به Gemini یا Groq ارسال نشده و هیچ اعتباری مصرف نشده است. آزمون کامل ظاهری و تعاملی در مرورگر واقعی نیز انجام نشده است.

## محدودیت‌های شناخته‌شده

- منطق اصلی برنامه هنوز تا حد زیادی در `js/app.js` قرار دارد؛ این نسخه بازنویسی کامل معماری نیست.
- `localStorage` تراکنش واقعی چندکلیدی ندارد؛ بازگردانی جدید بهترین‌تلاش است و جلوی تمام سناریوهای قطع ناگهانی برق یا بسته شدن مرورگر را تضمین نمی‌کند.
- همگام‌سازی ابری، حساب کاربری و پایگاه داده چندکاربره اضافه نشده‌اند.
- حالت مستقیم مرورگر برای Groq باقی مانده و برای انتشار عمومی مناسب نیست؛ از Secure Proxy (removed in personal build) برای نگه‌داشتن کلیدها در سمت سرور استفاده کنید.
- در Secure Proxy (removed in personal build) یک توکن مشترک وجود دارد و محدودیت نرخ در حافظه فرایند نگهداری می‌شود؛ برای سرویس عمومی به احراز هویت واقعی، سهمیه‌بندی هر کاربر، پایش، امنیت استقرار و کنترل سوءاستفاده نیاز است.
