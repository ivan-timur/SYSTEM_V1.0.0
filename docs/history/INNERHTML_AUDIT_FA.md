# گزارش بازبینی `innerHTML` — SYSTEM v5.8.0

## نتیجهٔ کلی

۲۵ عبارت `innerHTML` در پنج فایل JavaScript شناسایی شد. استفاده از `innerHTML` به‌خودی‌خود توسط CSP غیرفعال نمی‌شود؛ بنابراین دفاع این نسخه بر الگوی «قالب داخلی ثابت + escape ورودی + تبدیل عددی + whitelisting» استوار است. آزمون ایستای `tests/security-audit.js` این شروط کلیدی را به‌صورت خودکار بررسی می‌کند.

## `js/i18n.js` — ۲ مورد

هر دو مورد مربوط به دکمهٔ زبان است. HTML درج‌شده فقط یک `<span>` ثابت و برچسب‌های انگلیسی/فارسی ثابت دارد؛ هیچ ورودی کاربر یا رشتهٔ API در آن استفاده نمی‌شود.

## `js/rewards-plus.js` — ۲ مورد

- `renderHub()` تاریخچه و شمارنده‌های صندوق را نمایش می‌دهد. عنوان پاداش escape می‌شود؛ XP/Coins و شمارنده‌های صندوق هنگام خواندن storage به عدد صحیح محدود تبدیل می‌شوند. سطح جایزه (`tier`) از جدول داخلی ثابت می‌آید.
- `decorate()` فقط اسکلت ثابت `<i><em>` را می‌سازد و مقدار پیشرفت بعداً با `style.width` عددی و `textContent` درج می‌شود.

## دفاع‌های تکمیلی

- نقش پیام ذخیره‌شده در CSS class دیگر از storage کپی نمی‌شود.
- رکوردهای خالی یا غیرشیء در فهرست Inventory/Goals/Custom Quest فیلتر می‌شوند تا دادهٔ خراب باعث خطای زمان اجرا نشود.
- `eval`, `new Function`, `document.write` و attributeهای handler داخل HTML پیدا نشدند.
- CSP اسکریپت‌های inline را ممنوع می‌کند؛ مجوز `style-src 'unsafe-inline'` فعلاً فقط برای styleهای قدیمی و عرض پویای progress bar باقی مانده است.

**قانون توسعه:** هر sink تازهٔ `innerHTML` باید به این گزارش و به تست `tests/security-audit.js` افزوده شود. برای محتوای جدید و غیرساختاری، اولویت با `textContent`، `createElement()` و `replaceChildren()` است.
