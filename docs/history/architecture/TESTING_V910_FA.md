# راهنمای آزمون SYSTEM v9.1.0

## چه تغییری کرد؟

- محاسبهٔ XP بازیکن، Stat و Skill و تعیین Rank از یک ماژول مشترک به نام `js/core/progression-math.js` استفاده می‌کند.
- کنترل‌گر قدیمی برای سازگاری نام‌های موجود (`getPlayerXPRequired` و دیگر توابع) را نگه می‌دارد، اما دیگر منطق ریاضی را درون خودش پیاده‌سازی نمی‌کند.
- فایل `tests/progression-math-test.js` رفتار منحنی‌ها، آستانه‌های Rank، ورودی‌های نامعتبر، یکنواخت‌بودن مقادیر و سقف عددی را بررسی می‌کند.
- گردش‌کار GitHub Actions در `.github/workflows/quality.yml` آزمون‌های ایستا، بررسی سلامت و آزمون‌های Playwright را در هر Push و Pull Request اجرا می‌کند.

## اجرای بررسی روی دستگاه توسعه

```bash
npm install
npm test
npm run doctor
npx playwright install chromium
npm run test:e2e
```

فرمان `npm run test:e2e` هر دو پروژهٔ تعریف‌شده در `playwright.config.js` را اجرا می‌کند: Chromium دسکتاپ و شبیه‌سازی Pixel 7. اگر آزمونی شکست بخورد، Trace و Screenshot مربوطه در خروجی Playwright نگه‌داری می‌شود.

## نتیجهٔ این محیط

آزمون‌های Node و ساخت پروژه داخل محیط فعلی قابل اجرا هستند. آزمون تعاملی مرورگر در همین محیط تأیید نشد؛ Chromium مدیریت‌شده همهٔ URLها را با خط‌مشی `URLBlocklist: ["*"]` مسدود می‌کند، از جمله سرور آزمایشی محلی. به‌جای تغییر یا دورزدن خط‌مشی محیط، اجرای واقعی مرورگر به گردش‌کار CI منتقل شده است. تا زمانی که این گردش‌کار در یک مخزن GitHub اجرا نشود، نتیجهٔ E2E را موفق یا تأییدشده تلقی نکنید.

## مرز این مرحله از ماژولارسازی

این انتشار یک گام مهاجرت تدریجی است؛ منحنی‌های XP و Rank اکنون مستقل و قابل‌آزمون‌اند. `js/app-legacy.js` هنوز بخش‌های بزرگی از رابط و منطق برنامه را نگه می‌دارد و باید در انتشارهای بعدی با آزمون رگرسیون به ماژول‌های کوچک‌تر تقسیم شود، نه با بازنویسی یک‌باره.
