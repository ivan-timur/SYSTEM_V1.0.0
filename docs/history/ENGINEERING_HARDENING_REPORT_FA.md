# گزارش مهندسی و سخت‌سازی SYSTEM v5.8.0

## خلاصهٔ نسخه

نسخهٔ 5.8.0 روی ساختار واقعی پروژهٔ موجود ساخته شده است. داده‌های پیشرفت و کلیدهای ذخیره‌سازی بازطراحی نشده‌اند. تغییرات اصلی در هم‌نسخه‌سازی انتشار، حذف اجزای بلااستفاده، سخت‌سازی ورودی‌های HTML، یکپارچه‌سازی CSS، precache آفلاین و ایجاد آزمون‌ها متمرکز است.

## ۱. یکسان‌سازی نسخه

`VERSION` منبع اصلی نسخه است. اسکریپت `scripts/sync-version.js` هنگام ساخت، نسخه را در موارد زیر همگام می‌کند:

- `js/app.js` (نشان نسخه؛ مقدار اجرایی از ماژول نسخه وارد می‌شود)
- `js/modules/version.js`
- `js/app-legacy.js`
- `package.json`
- `manifest.webmanifest`
- `sw.js` از طریق سازندهٔ Service Worker

ساخت در صورتی که `CHANGELOG.md` فاقد بخش نسخهٔ جاری باشد، شکست می‌خورد. نام کش Service Worker نیز از همان نسخه ساخته می‌شود؛ بنابراین پس از ارتقا، کش قدیمی `system-v...` هنگام فعال‌شدن Service Worker حذف می‌شود.

## ۲. proxy و placeholderها

- رابط و مسیر کد مربوط به Secure Proxy حذف شد، چون در بستهٔ ارسالی پوشه یا پیاده‌سازی `backend/` وجود نداشت. هیچ backend ساختگی به پروژه افزوده نشده است.
- کلید API مستقیم Groq در حافظهٔ همان تب نگه داشته می‌شود؛ این کار معادل ذخیره‌سازی امن سمت سرور نیست.
- بیش از ۵۰ فایل JavaScript بی‌عملکرد که فقط placeholder ماژول بودند حذف شدند.
- ۱۴ صفحهٔ HTML مستقل که تنها پیام «مسیر آینده» نشان می‌دادند و از برنامهٔ اصلی فراخوانی نمی‌شدند حذف شدند. داشبورد فعلی Single-Page است و Service Worker دیگر این مسیرهای غیرفعال را پیش‌بارگذاری نمی‌کند.

## ۳. مهاجرت تدریجی به ES modules

`index.html` فقط یک نقطهٔ ورود `type="module"` بارگذاری می‌کند. `js/app.js` اکنون bootloader ماژولی است و سازگاری با اسکریپت‌های قدیمی را به ترتیب قطعی اجرا می‌کند.

ماژول‌های واقعی فعلی:

- `js/modules/version.js`: مقدار نسخهٔ اجرایی
- `js/modules/storage.js`: مرز ES-module برای سرویس ذخیره‌سازی و پشتیبان‌گیری موجود
- `js/modules/security.js`: ابزارهای سازگار با CSP و listener جایگزین رویداد خطای تصویر
- `js/modules/ai-workspace-navigation.js`: کنترل تب‌های AI با پشتیبانی صفحه‌کلید و ویژگی‌های دسترس‌پذیری

**محدودیت آگاهانه:** منطق اصلی هنوز عمدتاً در `js/app-legacy.js` است. این نسخه مهاجرت تدریجی را شروع کرده است و بازنویسی یک‌بارهٔ منطق پیشرفت، مأموریت‌ها و ذخیره‌سازی انجام نشده تا خطر شکستن ذخیره‌های فعلی کاهش یابد.

## ۴. CSP و بازبینی `innerHTML`

در `index.html` یک Content Security Policy اضافه شده است: اسکریپت‌ها فقط از مبدأ خود برنامه پذیرفته می‌شوند؛ `object-src` و `frame-src` بسته‌اند؛ `base-uri` و `form-action` محدود هستند؛ اتصال شبکه فقط به مبدأ خود برنامه، Groq و Google Generative Language اجازه داده شده است. handler درون‌خطی تصویر حذف و با listener ماژولی جایگزین شده است.

تمام ۲۵ استفادهٔ `innerHTML` در پنج فایل JavaScript بررسی شده‌اند. ورودی کاربر یا داده‌های ذخیره‌شده در موارد پویا escape یا به عدد/مقدار محدود تبدیل می‌شوند. به‌طور خاص، نقش پیام چت از storage دیگر مستقیماً در class وارد نمی‌شود؛ تاریخچهٔ پاداش و شمارنده‌های صندوق نیز پیش از درج در HTML نرمال‌سازی می‌شوند.

باقی‌ماندهٔ امنیتی شناخته‌شده: `style-src 'unsafe-inline'` فعلاً به‌دلیل عرض‌های پویا و style attributeهای قدیمی برای نوار پیشرفت نگه داشته شده است. این استثنا مجوز اجرای JavaScript درون‌خطی نمی‌دهد. فهرست sinkها و بررسی هر مورد در `INNERHTML_AUDIT_FA.md` است.

## ۵. CSS در یک لایه

- `index.html` فقط یک فایل CSS فعال دارد: `css/system.css`.
- سازندهٔ CSS، ۳۲ فایل منبع را با ترتیب مشخص در یک لایهٔ `@layer system` ترکیب می‌کند و آدرس دارایی‌ها را برای مسیر فایل bundle اصلاح می‌کند.
- تعداد ۱۱۷۹ توکن `!important` از فایل‌های منبع حذف شد. فایل نهایی و همهٔ فایل‌های CSS منبع در حال حاضر `!important` ندارند.
- فایل‌های منبع برای نگهداری قابل ویرایش باقی مانده‌اند؛ `css/system.css` خروجی تولیدشده است و باید از طریق `npm run build:css` دوباره ساخته شود.

چون قواعد پرقدرت CSS عمداً حذف شده‌اند و بررسی تصویری مرورگر در این محیط به نتیجه نرسید، ظاهر نهایی باید در مرورگر مقصد بررسی شود؛ تست‌های ایستا به‌تنهایی جایگزین بررسی بصری نیستند.

## ۶. Service Worker و precache

`npm run build:sw` لیست precache را از فایل‌های موجود در پوسته، `assets/`, `css/`, `data/` و `js/` می‌سازد. نسخهٔ فعلی **۹۶ منبع محلی** را پیش‌بارگذاری می‌کند. `cache.addAll(SHELL)` به‌صورت fail-fast اجرا می‌شود؛ اگر فایلی جا افتاده یا قابل‌دریافت نباشد، نصب Service Worker بی‌صدا موفق اعلام نمی‌شود.

## ۷. آزمون‌ها

نتیجهٔ آخرین اجرای `npm test`:

- ۱۷۵ بررسی Smoke/Unit موفق
- ۲۰ بررسی ذخیره‌سازی موفق
- ۵ بررسی snapshot خودکار موفق
- ۵۷ بررسی audit امنیت، نسخه، CSS و precache موفق
- ۹ تم شناخته‌شده و ۲۲ فایل JSON اعتبارسنجی‌شده
- بررسی نحوی همهٔ فایل‌های JavaScript و JSONهای manifest/package موفق

Playwright با سه سناریو برای Status، Quest، RTL، موبایل و CSP افزوده شده و دو پروژهٔ مرورگر دارد: Chromium دسکتاپ و Pixel 7 mobile emulation. **آزمون‌های Playwright در این محیط اجرا نشدند**: نصب وابستگی‌ها زمان‌بر و timeout شد و اجرای headless Chromium محلی نیز در این محیط متوقف ماند. بنابراین نتیجهٔ بصری یا نتیجهٔ واقعی Playwright تأییدشده محسوب نمی‌شود.

برای اجرای آزمون مرورگری روی سیستمی با Node.js:

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

برای فقط آزمون موبایل:

```bash
npm run test:e2e:mobile
```
