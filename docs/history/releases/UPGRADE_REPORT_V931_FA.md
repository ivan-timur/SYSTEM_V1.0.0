# گزارش اصلاحات SYSTEM v9.3.1

## اصلاح‌شده در این بسته

1. پیکربندی GitHub Actions برای آزمون‌های مرورگر اصلاح شد: Playwright قبل از اجرا نصب می‌شود و تنظیم کش npm که به lockfile غایب نیاز داشت حذف شد.
2. نام Artifact مربوط به APK آزمایشی مستقیماً از `VERSION` گرفته می‌شود و با نسخه‌های آینده ثابت نمی‌ماند.
3. دو فایل CSS موجود ولی حذف‌شده از ساخت (`apex-evolution.css` و `rebirth-core.css`) دوباره در ترتیب ساخت قرار گرفتند.
4. مسیرهای فعال Gemini API، متغیرها، تست‌های مربوط و اجازهٔ اضافی CSP حذف شدند؛ Groq تنها ارائه‌دهندهٔ خارجی باقی مانده است.
5. آزمون ساخت درخواست Groq اضافه و آزمون‌های امنیت/یکپارچگی برای حذف Gemini و آماده‌بودن CI به‌روزرسانی شدند.
6. مسیر آپدیت اندروید اکنون فایل `SYSTEM-version.apk.sha256` را از همان Release می‌خواند و پیش از اجرای نصب‌کننده SHA-256 فایل APK را بررسی می‌کند؛ Release بدون checksum مسدود می‌شود.
7. نسخهٔ پروژه به 9.3.1 افزایش یافت و خروجی CSS، Service Worker و دارایی‌های Android با نسخهٔ جدید همگام شد.

## نتایج تأییدشده

- `npm run prepare:android`: موفق؛ 116 فایل در حجم تقریبی 5.66 MiB همگام شد.
- `npm test`: تمام آزمون‌های ایستای موجود موفق شدند، از جمله آزمون جدید ساخت درخواست Groq و کنترل نام Artifact نسخه‌محور.
- `npm run doctor`: موفق.
- بررسی نحوی 54 فایل JavaScript: بدون خطا.
- CSS از 59 منبع ساخته شد؛ باندل خروجی 0 اعلان `!important` دارد.
- Service Worker شامل 117 منبع precache است.

## محدودیت‌های باقی‌مانده

- Playwright E2E اجرا نشد، چون وابستگی و Chromium در این محیط نصب نیستند و ارتباط با registry npm برقرار نشد. اکنون Workflow گیت‌هاب نصب وابستگی را پیش از اجرای E2E انجام می‌دهد؛ اجرای موفق آن روی GitHub Actions هنوز تأیید نشده است.
- APK کامپایل نشد، چون Android SDK و Gradle در محیط موجود نیستند. Workflow ساخت APK از روی گیت‌هاب آمادهٔ اجرا است، اما ساخت موفق و آزمایش روی گوشی واقعی هنوز نیازمند اجرای آن است.
- نصب به‌روزرسانی روی اندروید باید با تأیید کاربر انجام شود؛ این پروژه نصب بی‌صدا/بی‌اجازه را پیاده‌سازی نمی‌کند.
