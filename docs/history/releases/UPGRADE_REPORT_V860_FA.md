# گزارش اصلاحات و سخت‌سازی SYSTEM v8.6.0

**تاریخ:** 2026-10-15  
**مبنای ارتقا:** `SYSTEM_v8.5.9_REWARDS_CITADEL.zip`

## تغییرات انجام‌شده

### 1. یکسان‌سازی نسخه و راهنمای پروژه
- `VERSION` به منبع یگانهٔ نسخه باقی ماند و نسخه به `8.6.0` ارتقا یافت.
- فرایند build حالا نسخهٔ عنوان README را نیز با `VERSION` همگام می‌کند.
- راهنمای اجرا اصلاح شد: پروژه به علت ES Modules و Service Worker نباید با `file://` اجرا شود؛ سرور محلی HTTP روش پیشنهادی است.
- `docs/STRUCTURE.md` از طرح قدیمی نسخهٔ 6.3 به نقشهٔ معماری فعلی تبدیل شد.

### 2. خطای قابل‌مشاهده در راه‌اندازی
- اگر یکی از اسکریپت‌های موردنیاز بارگذاری نشود، برنامه اکنون حالت `error` ثبت می‌کند و یک پیام قابل‌دسترسی نمایش می‌دهد.
- پیام خطا با `textContent` ساخته می‌شود، نه با واردکردن رشتهٔ خطا به‌عنوان HTML.
- حالت‌های `starting`، `ready` و `error` برای تشخیص وضعیت راه‌اندازی فراهم شدند؛ رویدادهای `system-app-ready` و `system-app-error` نیز منتشر می‌شوند.

### 3. اصلاح اجرای E2E و تشخیص پروژه
- اجرای Playwright از یک wrapper محلی می‌گذرد که ابتدا نصب بودن `@playwright/test` را تأیید می‌کند.
- در صورت نبودن وابستگی، دستور راه‌اندازی لازم را نشان می‌دهد و دیگر به‌شکل تصادفی CLI سراسری و نامرتبط را اجرا نمی‌کند.
- فرمان `npm run doctor` برای بررسی فایل‌های اصلی، فرادادهٔ نسخه و وضعیت وابستگی Playwright اضافه شد.

### 4. روشن‌شدن نقش پوشهٔ data
- بررسی منابع اجرایی نشان داد JSONهای `data/` در نسخهٔ مبنا منبع runtime برنامه نیستند؛ تعریف‌های فعال عمدتاً در HTML و JavaScript هستند.
- این محدودیت در README، نقشهٔ معماری و `data/README.md` صریح شد.
- فایل‌های غیرمصرف‌شدهٔ `data/` از precache برنامه خارج شدند تا فضای کش آفلاین صرف منابع runtime شود.
- این کار عمداً وانمود نمی‌کند که مهاجرت کامل به منبع دادهٔ واحد انجام شده است؛ آن مهاجرت به schema، سازگاری داده‌های ذخیره‌شده و آزمون رگرسیون نیاز دارد.

### 5. پاک‌سازی اسناد خالی و آزمون یکپارچگی
- 28 فایل Markdown صفر‌بایتی که هیچ محتوای گزارشی نداشتند حذف شدند؛ اسناد تاریخی دارای محتوا حفظ شده‌اند. فهرست حذف‌ها در `docs/history/EMPTY_PLACEHOLDERS_REMOVED_FA.md` ثبت شده است.
- آزمون یکپارچگی جدید، نسخه‌ها، فایل‌های بارگذاری‌شده از نقطهٔ ورود، خروجی CSS، مستندات، پیام خطای bootstrap و تنظیمات E2E را بررسی می‌کند.

## محدودیت بررسی

**آزمون واقعی Playwright هنوز اجرا نشده است.** در محیط حاضر، وابستگی محلی `@playwright/test` نصب نبود و نصب npm در این محیط به پایان نرسید. دستور E2E اکنون این وضعیت را روشن گزارش می‌دهد. بنابراین ظاهر واقعی همهٔ صفحات، تعامل‌های مرورگر و اندازه‌های موبایل را تأییدشده فرض نکن.

## مشکلات مهمی که هنوز به مرحلهٔ بعد نیاز دارند

1. **تبدیل JSONهای `data/` به مرجع واقعی داده** یا حذف کامل آن‌ها پس از تصمیم معماری؛ در این انتشار صرفاً نقششان مستند شده است.
2. **اتصال واقعی Goal → Milestone → Quest → Evidence → Skill Progression → Reward** با شناسه‌های پایدار و قابل‌ردیابی.
3. **ماژولارسازی تدریجی `js/app-legacy.js`** بدون بازنویسی ناگهانی و با آزمون رگرسیون.
4. **اجرای آزمون‌های Playwright و screenshot regression** در محیطی با وابستگی و مرورگر نصب‌شده.
5. **آزمون سناریوهای چندتب، ذخیره‌سازی پر/غیرفعال و خطای شبکه**؛ آزمون‌های ایستا به‌تنهایی تمام رفتار مرورگر را پوشش نمی‌دهند.

## جمع‌بندی

نسخهٔ 8.6.0 یک پاس سخت‌سازی واقعی بر پایهٔ مشکلات قابل‌تأیید است: نسخه و مستندات هم‌راستا شده‌اند، خطای bootstrap قابل‌دیدن شده، مسیر E2E واضح‌تر شده، کش آفلاین سبک‌تر شده و آزمون یکپارچگی افزوده شده است. مشکلات معماری عمده عمداً با بازنویسی پرخطر پنهان نشده‌اند و در بخش «محدودیت‌ها» دقیقاً مشخص شده‌اند.
