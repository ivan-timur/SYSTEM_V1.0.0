# گزارش ارتقای SYSTEM v8.8.0

**عنوان انتشار:** Goal Integrity, Data Validation & Dari UX  
**تاریخ:** ۱۵ اکتبر ۲۰۲۶  
**نسخهٔ پایه:** SYSTEM v8.7.0 Goal Evidence & Rewards Hardened  
**وضعیت:** آزمون‌های ایستا، اعتبارسنجی ساخت، بررسی سلامت پروژه و ممیزی نحوی JavaScript موفق؛ آزمون تعاملی واقعی مرورگر تأیید نشده است.

## خلاصهٔ اجرایی

تمرکز این نسخه بر سه ریسک بود: امکان پذیرفته‌شدن تاریخ‌های ناممکن، ناسازگاری شمارندهٔ پیشرفت Goal با شواهد واقعی، و ناقص‌بودن ترجمهٔ دری در گردش‌کار Goal و سلامت اطلاعات.

## تغییرات پیاده‌سازی‌شده

### ۱. پیشرفت Goal اکنون از شواهد یکتا محاسبه می‌شود

- `progressCount` دیگر یک شمارندهٔ مستقل و قابل‌اعتماد فرض نمی‌شود؛ مقدار نرمال‌شده از تعداد شواهد یکتای معتبر محاسبه می‌شود.
- شمارندهٔ ذخیره‌شده‌ای که با شواهد واقعی سازگار نباشد، نمی‌تواند هنگام خواندن Goal باعث پیشرفت بدون مدرک شود.
- اعتبارسنجی Backup سازگاری `progressCount` با Evidence را بررسی می‌کند.
- Backup دارای Goal فعال با پیشرفت کامل، Goal تکمیل‌شده با حالت تکمیل نامعتبر، یا تکمیل مبتنی بر شواهد بدون شواهد کافی رد می‌شود.
- حالت تکمیل دستی همچنان جداگانه پشتیبانی می‌شود و برای آن وجود شواهد تا سقف هدف الزامی نیست.

### ۲. اعتبارسنجی واقعی تاریخ و زمان

- تاریخ‌های هدف، تاریخ Daily Prize و تاریخ مأموریت روزانه از نظر تقویمی بررسی می‌شوند؛ رشته‌ای با قالب درست ولی روز ناممکن مانند `2026-02-30` پذیرفته نمی‌شود.
- زمان ثبت شواهد، `createdAt` و `completedAt` در Backup باید زمان معتبر ISO-8601 با تاریخ تقویمی واقعی باشند.
- نرمال‌سازی Goal، تاریخ ناممکن را نگه نمی‌دارد و شواهد دارای زمان نامعتبر را وارد لیست معتبر نمی‌کند.

### ۳. شناسه‌های پایدار و داده‌های تکراری

- شناسه‌های Inventory که ابتدا یا انتهایشان فاصلهٔ اضافی دارد، در اعتبارسنجی Backup رد می‌شوند.
- بررسی Backup شناسه‌های Goal، Store و Custom Quest را نیز از لحاظ فاصله‌های اضافی و تکرار سخت‌گیرانه‌تر بررسی می‌کند.
- خواندن Inventory، Store و Custom Quest دیگر شناسه‌های دارای فاصلهٔ ابتدا/انتها را در داده‌های زنده نمی‌پذیرد.

### ۴. بهبود تجربهٔ زبان دری

ترجمه‌های رابط برای بخش‌های زیر گسترش یافتند:

- ساخت Goal، شاخهٔ پیشرفت، مهلت، هدف تعداد مأموریت و وضعیت شواهد؛
- وضعیت‌های تکمیل دستی و تکمیل تأییدشده با مأموریت؛
- ساخت Custom Quest و گزینهٔ وصل‌کردن آن به Goal؛
- پنل سلامت ذخیره‌سازی و اقدامات Export/Restore؛
- پیام‌های مهم دربارهٔ مشکلات داده و تهیهٔ نسخهٔ پشتیبان.

عبارت‌های ثابت وضعیت Goal در HTML از مقادیر متغیر جدا شدند تا کنترل ترجمهٔ پویا مطمئن‌تر باشد.

## محدودیت‌ها و کارهای باقی‌مانده

- `npm run test:e2e` هنوز اجرا نشد؛ وابستگی محلی `@playwright/test` در محیط فعلی نصب نیست. بنابراین تعامل واقعی کاربر، ظاهر مرورگر و اندازه‌های موبایل در این انتشار به‌صورت خودکار تأیید نشده‌اند.
- `js/app-legacy.js` هنوز فایل بزرگی است. تقسیم آن به ماژول‌های مستقل باید مرحله‌به‌مرحله و با آزمون بازگشت قابلیت‌ها انجام شود.
- فایل‌های JSON در پوشهٔ `data/` هنوز منبع اصلی داده‌های زمان اجرا نیستند.
- داده‌ها عمدتاً محلی هستند؛ همگام‌سازی ابری یا چنددستگاهی در این نسخه پیاده‌سازی نشده است.

