# گزارش اصلاح یکپارچگی XP — SYSTEM v8.3.2

## خلاصه

در نسخه 8.3.1 دو مسیر مستقل برای تغییر پیشرفت وجود داشت: کد تکمیل مأموریت می‌توانست XP بازیکن و گاهی XP شاخه را اضافه کند، درحالی‌که `recordSystemEvent()` هنگام ثبت تاریخچه به‌صورت پنهانی XP مهارت را افزایش می‌داد. این جدایی باعث می‌شد یک گره Skill XP بگیرد، بی‌آنکه Stat والد آن XP دریافت کند.

در نسخه 8.3.2 این اثر جانبی حذف شد و یک تابع مرکزی به نام `applyProgressionReward()` برای پاداش مأموریت‌ها ایجاد شد.

## سیاست جدید پیشرفت

### مأموریت وابسته به یک شاخه

وقتی مأموریت یک Stat معتبر مانند Mathematics یا Computer داشته باشد، همان تکمیل مأموریت در یک تراکنش واحد این مراحل را انجام می‌دهد:

1. افزودن XP به Player.
2. افزودن همان مقدار XP به Stat انتخاب‌شده.
3. تعیین Skill منطبق با عنوان/توضیح یا شناسه صریح، فقط در صورت وجود تطبیق قابل‌اعتماد.
4. بررسی پیش‌نیازهای Skill قبل از اعطای Skill XP.
5. افزودن سکه‌ها و ثبت رویداد تاریخچه با همان Stat و شناسه Skill اعتبارسنجی‌شده.

مقدار Skill XP مطابق سیاست قبلی محاسبه می‌شود (۵۰٪ XP فعالیت) و گره‌های مجاز مسیر والد نیز می‌توانند پیشرفت دریافت کنند. اگر Skill قابل‌اعتمادی پیدا نشود، XP بازیکن و Stat ثبت می‌شود اما XP به گره تصادفی داده نمی‌شود.

### مأموریت عمومی

مأموریتی که Stat ندارد، فقط XP بازیکن و سکه‌های تعریف‌شده را اعطا می‌کند. موتور دیگر از عنوان مأموریت یک شاخه یا Skill را به‌صورت پنهانی حدس نمی‌زند.

در فرم‌های جدید Goal و Custom Quest، کاربر باید شاخه مربوطه را صریحاً انتخاب کند یا گزینه «General — Player XP only» را برگزیند. Goal و Custom Quest قدیمی که متادیتای شاخه ندارند، به‌صورت امن عمومی تلقی می‌شوند و به‌طور خودکار به شاخه‌ای نسبت داده نمی‌شوند.

Boss Questهای فعلی نیز تا وقتی برایشان Stat مشخص نشده، پاداش عمومی بازیکن می‌دهند؛ اگر در آینده `stat` معتبر به تعریف یک Boss Quest افزوده شود، همان موتور مرکزی آن را پردازش می‌کند.

## مسیرهایی که به موتور مرکزی منتقل شدند

- Daily Quest
- AI Daily Quest
- Goal
- Boss Quest
- Custom Quest

پاداش ورود روزانه و خرید/دریافت جوایز از فروشگاه همچنان خارج از پیشرفت یادگیری باقی مانده‌اند؛ بنابراین، به‌صورت عمدی XP شاخه یا مهارت نمی‌دهند.

## ایمنی و سازگاری

- شناسه Stat نامعتبر پیش از هر تغییر پاداش رد می‌شود.
- شناسه Skill بدون Stat معتبر رد می‌شود.
- رویداد تاریخچه دیگر XP اعطا نمی‌کند؛ فقط نتیجه ثبت‌شده در موتور مرکزی را نگهداری می‌کند.
- مسیرهای تکمیل مأموریت همچنان از `runSystemTransaction()` استفاده می‌کنند تا در صورت شکست ذخیره‌سازی، تغییرات ناقص برگشت داده شوند.
- شناسه نسخه و مستندات به 8.3.2 هماهنگ شده‌اند.
