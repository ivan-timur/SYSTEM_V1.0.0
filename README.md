## فاز ۱۳ — مسیر تطبیقی یادگیری

موتور `adaptive-learning-path` پیشنهادهای مأموریت را با توجه به نمره‌های پایین، مرورهای سررسیدشده، هدف و نقطهٔ عطف فعال، زمان در دسترس و پیش‌نیازهای تأییدشده رتبه‌بندی می‌کند. این موتور قطعی و بدون اثر جانبی است: داده ذخیره نمی‌کند، تسلط را خودش تأیید نمی‌کند و پاداش نمی‌دهد. در این فاز موتور تایپ‌شده و آزمون‌های آن اضافه شده‌اند؛ اتصال خودکار پیشنهادها به صفحهٔ زنده هنوز نیازمند فاز UI جداگانه است.


این نسخه بازخورد بصری واقعی برای ارتقای سطح، رتبه و Claim نشان‌ها را اضافه می‌کند. از Settings → Visual Effects می‌توان فضای کیهانی و جشن‌های ارتقا را جداگانه کنترل کرد؛ ترجیحات در کلید محلی مستقل ذخیره می‌شوند و قوانین پیشرفت یا پاداش‌ها را تغییر نمی‌دهند. تنظیم کاهش حرکت رعایت می‌شود و WebGL تا زمان اثبات نیاز به تعویق افتاده است.

**SYSTEM** برنامه‌ای local-first برای مدیریت هدف‌ها، عادت‌ها، یادگیری، مهارت‌ها و پاداش‌های شخصی است. داده‌های اصلی روی همان مرورگر/دستگاه نگه‌داری می‌شوند؛ قابلیت‌های متصل به هوش مصنوعی به اینترنت نیاز دارند.

## فاز ۷ — یکپارچگی شواهد هدف و مرز تراکنش اتمی (2026-10-19)

مهاجرت تأییدشدهٔ اطلاعات قدیمی اکنون Goalها را به مسیرهای آموزشی تایپ‌شده با milestoneهای پیاپی تبدیل می‌کند و شواهد معتبر را هم در snapshot هدف و هم در دفتر شواهد افزایشی IndexedDB می‌نویسد. شواهد تاریخی فقط زمانی پذیرفته می‌شوند که به مأموریت سفارشی واردشده و واقعاً تکمیل‌شده اشاره کنند؛ شناسهٔ گم‌شده یا مأموریت باز به‌عنوان مدرک پیشرفت ثبت نمی‌شود. شواهد ردشده نیز جای milestone را اشغال نمی‌کنند و سابقهٔ قدیمی هرگز به‌تنهایی تسلط مهارت را تأیید نمی‌کند.

در API پایدار IndexedDB، مأموریت متصل به هدف بدون `curriculumEvidence` در همان فرمان تراکنشی تکمیل نمی‌شود. در مسیر پشتیبانی‌شده، تکمیل Quest، تغییر پیشرفت Player/Skill/Stat، دفتر XP، شمارنده‌ها، سابقهٔ فعالیت، snapshot هدف و ردیف شواهد در یک تراکنش ذخیره می‌شوند؛ شکست باید کل تراکنش را لغو کند. آزمون‌های TypeScript و static regression اجرا شده‌اند. آزمون واقعی مرورگر نیز تلاش شد، اما سیاست مدیریتی Chromium دسترسی به localhost را با `ERR_BLOCKED_BY_ADMINISTRATOR` مسدود کرد؛ بنابراین موفقیت واقعی IndexedDB در مرورگر تأیید نشده است.

**محدودیت مهم:** این فاز مرز پایدار و مهاجرت را ایمن‌تر می‌کند، اما مسیر زندهٔ همهٔ بخش‌های رابط اصلی هنوز از `localStorage` استفاده می‌کند. این نسخه را نباید به‌عنوان انتقال کامل برنامه به IndexedDB یا تأیید نصب APK روی دستگاه واقعی تلقی کرد.

## فاز ۶ — گردش‌کار قابل‌بازبینی مهاجرت و دروازهٔ Cutover (2026-10-19)

در Settings → Backup یک پنل برای **Review current save** اضافه شده است. ابتدا خلاصه و هشدارهای دادهٔ فعلی نمایش داده می‌شود؛ سپس واردکردن فقط با تأیید صریح انجام می‌شود. وضعیت پایگاه با یک رسید فقط‌خواندنی و fingerprint مقایسه می‌شود. اگر `localStorage` پس از واردکردن تغییر کرده باشد، رابط برنامه واگرایی دو نسخهٔ داده را گزارش می‌کند و از ادعای همگام‌بودن جلوگیری می‌کند.

مهاجرت خودکار نیست، پیش‌نمایش باید تازه باشد، مقصد غیرخالی پذیرفته نمی‌شود و کلیدهای اصلی `localStorage` حذف نمی‌شوند. **این فاز IndexedDB را هنوز منبع فعال همهٔ بخش‌های برنامه نمی‌کند.** برخی مسیرهای پاداش هنوز در کنترل‌گر قدیمی ذخیره می‌شوند؛ بنابراین دروازهٔ تغییر منبع اصلی بسته می‌ماند تا تمام مسیرهای پاداش و بازیابی در یک طرح واحد آزمایش شوند. آزمون قراردادی جدید گردش‌کار مهاجرت را در `npm test` کنترل می‌کند؛ موفقیت آزمون واقعی مرورگر یا نصب APK از این آزمون استنتاج نمی‌شود.

## فاز ۵ — ذخیره‌سازی اتمی Goal و شواهد (2026-10-19)

طرح تایپ‌شدهٔ IndexedDB در schema v7 فروشگاه‌های `goal_curricula` و `goal_evidence` را اضافه می‌کند. در API اختیاری `window.SYSTEMDurableCurriculumProgression`، تکمیل مأموریت متصل به Goal، پیشرفت Player/Skill، سابقهٔ XP، snapshot هدف و ردیف شواهد در یک تراکنش `readwrite` انجام می‌شوند؛ خطا باعث لغو تراکنش می‌شود و تکرار همان تکمیل دوباره شواهد یا پاداش هدف را اضافه نمی‌کند. API هنوز به‌صورت پل آزمایشی و اختیاری است: رابط اصلی همچنان از `localStorage` استفاده می‌کند و هیچ مهاجرت یا نوشتن دوگانهٔ خودکاری انجام نمی‌شود. آزمون‌های واحد و قراردادی در `npm test` اجرا می‌شوند؛ اجرای زندهٔ مرورگر در محیطی با سیاست مدیریتی مسدودکنندهٔ localhost نیازمند CI یا دستگاه مجاز است.

## وضعیت معماری نسخهٔ 3.2.0

نسخهٔ 3.2.0 بازخورد سطح و رتبه را پس از موفق‌شدن تراکنش نمایش می‌دهد و برای نشان‌ها پس از Claim موفق، پیام جداگانه دارد. از Settings → Visual Effects دو ترجیح مستقل مدیریت می‌شود؛ این ماژول فقط کلید `system_v3_visual_settings` را می‌خواند/می‌نویسد و مالک امتیاز یا دادهٔ پیشرفت نیست. در نسخهٔ 3.0.0، API مهاجرت `localStorage` به `IndexedDB` به گردش‌کار preview → approve → migrate تغییر کرده است. تأیید به fingerprint دقیق داده‌های قدیمی و تاریخ محلی گره خورده؛ اگر داده تغییر کند یا روز عوض شود، عملیات پیش از بازکردن IndexedDB متوقف می‌شود. هشدارهای Preview باید صریحاً تأیید شوند. کلیدهای قدیمی حفظ می‌شوند و مهاجرت خودکار انجام نمی‌شود؛ IndexedDB هنوز منبع فعال UI نیست.

## وضعیت معماری نسخهٔ 2.7.0

محاسبات XP/Level/Rank، معیارهای هشت Achievement پویا، قواعد Activity Ledger و قرارداد وضعیت Daily Quest در هستهٔ TypeScript قرار دارند. در نسخهٔ 2.7.0، خواندن/نرمال‌سازی و ساخت payload مأموریت‌های روزانه به TypeScript منتقل شده است؛ کنترل‌گر در این مسیر هماهنگی UI و نوشتن از راه آداپتور ذخیره‌سازی را نگه می‌دارد. نسخهٔ 2.6.0 اعتبارسنجی رویدادها، شمارنده‌های مادام‌العمر، ثبت شواهد یادگیری و خلاصه‌سازی فعالیت‌ها را از کنترل‌گر قدیمی جدا کرد و نوشتن رویداد را پیش از تغییر حافظه انجام می‌دهد. نسخهٔ 2.5.0 معیارهای Achievement را از کنترل‌گر جدا کرد و نگهبان خودکار معماری را اضافه نمود. نسخهٔ 2.4.0 نیز اجرای آزمون واقعی IndexedDB را وارد دروازهٔ CI کرد. این محیط فعلی همچنان سیاست مدیریتی مسدودکنندهٔ صفحات محلی دارد؛ در نتیجه آزمون واقعی در اینجا قابل اجرا نیست. مسیر UI زنده همچنان `localStorage` را منبع معتبر نگه می‌دارد تا دروازهٔ مرورگر در CI یا محیط مجاز واقعاً سبز شود.

## اجرای محلی

به‌دلیل استفاده از ES Modules و Service Worker، فایل `index.html` را مستقیماً با `file://` باز نکن. در ریشهٔ پروژه اجرا کن:

```bash
python -m http.server 8000
```

سپس `http://127.0.0.1:8000` را در مرورگر باز کن.

## ساخت و آزمون

پیش‌نیاز: Node.js نسخهٔ 20 یا جدیدتر و npm.

```bash
npm install --no-audit --no-fund
npm run build
npm test
npm run doctor
```

برای آزمون واقعی تراکنش‌های IndexedDB در مرورگر، وابستگی‌های پروژه و مرورگر Playwright را آماده کن:

```bash
npm install --no-audit --no-fund
npx playwright install chromium
npm run test:browser-idb
```

اجراکننده ابتدا از Chromium مشخص‌شده توسط Playwright استفاده می‌کند و در صورت نصب‌نبودن Playwright به اجراکنندهٔ CDP وابسته به Chromium سیستم برمی‌گردد. اگر سیاست مدیریتی مرورگر localhost را مسدود کرده باشد، اجراکننده فقط تشخیص می‌دهد و سیاست را تغییر نمی‌دهد؛ آزمون را نیز موفق اعلام نمی‌کند. در مخزن، دروازه‌های CI کیفیت و انتشار پس از نصب Playwright همین آزمون IndexedDB را پیش از آزمون‌های UI اجرا می‌کنند. برای آزمون تعاملی End-to-End رابط کاربری:

```bash
npx playwright install chromium
npm run test:e2e
npm run test:e2e:mobile
```

`npm run build` نسخه را از `VERSION` همگام می‌کند، CSS نهایی را می‌سازد و Service Worker را تولید می‌کند. برای بررسی مرزهای معماری اجرا کن: `npm run architecture:check`. برای بسته‌بندی اندروید پس از هر تغییر وب اجرا کن: `npm run prepare:android`. نقشهٔ نهایی فناوری‌ها و مراحل مهاجرت در [`docs/ARCHITECTURE_ROADMAP_FA.md`](docs/ARCHITECTURE_ROADMAP_FA.md) قرار دارد.

## امنیت و حفاظت از داده

از نسخهٔ ۱.۶.۰، پاداش‌های دارای شناسهٔ پایدار یک دفتر جلوگیری از پرداخت تکراری دارند. این محافظ در ذخیره‌سازی محلی و داخل مرز rollback برنامه عمل می‌کند؛ به‌دلیل ماهیت هم‌زمان `localStorage`، جایگزین تراکنش پایگاه‌داده یا همگام‌سازی تضمین‌شده بین دستگاه‌ها نیست.

کلید AI در `localStorage` ذخیره نمی‌شود، اما استفاده از کلید در سمت مرورگر همچنان به‌اندازهٔ نگه‌داری آن در سرور امن نیست. پیش از پاک‌کردن داده‌های مرورگر یا نصب مجدد، از تنظیمات یک Backup خروجی بگیر. نام‌های داخلی و کلیدهای ذخیره‌سازی قدیمی عمداً حفظ شده‌اند تا نسخهٔ جدید داده‌های موجود را از دست ندهد.

### Phase 12 — Durable skill assessment history
The Mastery Tracker stores its self-assessment records in the dedicated IndexedDB `skill_assessments` store. Existing `system_v2_skill_assessments` localStorage records are copied forward when possible and are not automatically deleted. Quiz attempts remain in the separate `assessment_attempts` store. Saving an assessment does not grant XP, coins, or rewards.

### Deep Logic Phase 3 — Curriculum Commands

The typed curriculum domain now exposes `addCurriculumMilestone`, `recordCurriculumEvidence`, and `getCurriculumCompletionDecision` from `src/features/curriculum-command.ts`. These commands return validated immutable snapshots and evaluation results; they do not persist data or issue rewards. A storage adapter should commit the returned snapshot within the existing transaction and discard it if any validation or persistence step fails. Run `npm test` to execute the full build and regression suite, including the new curriculum-command tests.
